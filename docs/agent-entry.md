# DSH 主会话中的插件专家

版本 `@oxmumu3/dsh-plugin-finder@0.12.0-preview.1`，本轮准确目标为官方 Harness `0.2.1-rc.5`、Node `^22.19.0 || >=24.0.0`，四个官方 SDK peer 固定 `0.2.1-rc.5`。发布与实际场景覆盖以对应发行回执为准；本说明不表示外部 MCP/A2A 接入已实现。

## 用户只交代原任务

用户直接向标准 Agent 描述要得到的结果。原生能力足够时继续完成；确实需要插件时，Agent 按需调用 Finder，核对现成能力、安装或补齐后接回原会话。用户无需先进入工作台重新描述，也不用理解内部 Creator 交接。

方案覆盖五种情况：原生足够、单个现成插件、2–4 个现成插件组合、具体缺口创造，以及混合方案。混合方案保留 1–4 个现成插件，并逐项记录缺失能力与原因；已有能力不因进入创造而丢弃，只为真正的缺口生成新的持久工具、交互或状态能力。

## 四个宿主工具

| 工具 | 职责 |
| --- | --- |
| `finder_lookup` | 理解当前任务需要，查找并记录精确来源、候选与方案；不把搜索覆盖不足当市场不存在。 |
| `finder_activate` | 对可直接使用的现成方案，通过官方管理器准备精确插件，回读实际启用后交回原任务。 |
| `finder_create` | 在原请求中补齐具体缺口；混合方案保留现成部分，官方 Creator 只负责缺失部件，受控安装后继续原任务。 |
| `finder_status` | 读取同一请求的真实状态与回执；结果未知时观察，不盲目重装、重派或重发原任务。 |

这些工具随当前 Agent 的真实可见工具注入路由提示。搜索结果本身不会新增权限；Host 代码、首次安装、构建脚本及工具调用沿用宿主当前授权和审批。

请求身份来自宿主主会话与注册工作区，不接受模型自报用户、会话或安装地址。每个请求保留独立耐久历史；原 Finder 工作台历史、草稿、机会发现授权和集中回传同意不因此迁移。必要上下文沿用宿主模型处理，不默认读取整个项目、私人会话或浏览记录。

## 创建、安装与原任务接续

创建通过官方 `cordis` 受管子任务处理有界规格。子任务在工作区生成、测试源码，不自行安装或发布；父 Agent 受控核对产物、归档精确字节并安装。实际加载确认后，仍由原 Agent 完成用户交代的任务。

生成源码与 `.finder-install-*` 本地制品保留供恢复和追溯，不要当作已经公开发布的包，也不要随意删除仍被安装引用的源码目录。已有现成插件和新生成部分分别保留来源、版本与安装结果。

产物校验或首装明确失败时，可在原请求通过 `finder_create.feedback` 发起最多两次有界修复，保留旧失败与回执。新尝试使用独立源码、包身份和数据目录；审批、重启要求、正在运行或未知状态不会被当作代码缺口盲目重派。只在有完整本请求来源证明时可逆停用对应旧失败包，不清数据或覆盖别人的安装。

已完成且尚未提交安装的产物，也可根据明确的代码审查反馈在原请求中修订。系统先只读复核原产物身份、源码指纹与当前未安装观察，再记录为调用方审查报告；这不等于宿主独立验证了漏洞，审批拒绝也不等于代码失败。没有完整来源、安装状态未知或已有安装时，不走这条修订路径；旧源码、现成能力和回执继续保留。

恢复只观察已绑定原子任务，并核对原始规格、宿主位置和结构化完成证据。跨工作区读取、安装或恢复被拒绝；工作区绑定不等于安装沙箱，profile 内安装仍会影响其他会话。管理器没有来源 CAS，不宣称对外部并发编辑提供原子覆盖保证。

## 结果与数据边界

找到候选、插件安装 active、Creator 一轮结束与原任务达到目标是不同事实。页面优先展示实际会话及可读取产物；计划复用或待补齐标签不证明它们已运行。最终按原任务的产物和约束验收，不能把 completed 自动改写成“需求已解决”。

需求理解、机会发现、创建与执行沿用宿主模型和账户额度。查询词用于外部检索，需求与候选资料会交给宿主配置的模型；第三方插件可能另有账号、授权或费用。Agent 请求不继承工作台集中回传授权；共创及其派生记录默认只存本机。

真实首装、组合、混合补齐和原任务完成结果应按发行回执的具体场景核对；不能据此推导任意插件、所有组合、外部客户端或多租户服务均已可用。
