## 产品行为

在 DSH 宿主侧栏增加一个“发现好插件”入口，在独立 main 面板内完成需求理解、真实候选检索、方案确认和会话草稿接续。不替换宿主侧栏、会话、composer 或应用根。

用户主动提交需求才调用宿主已配置模型；先解析目标、材料、产出、硬约束、能力及查询词，允许用户修改；随后在附带的真实索引中检索，再用同一宿主模型给出少量候选与最小方案。推荐必须允许原生够用、单插件、至多两个插件的组合及缺供给。模型仅能引用给定候选 ID，来源、版本、依赖和核验状态由服务端的索引记录提供，模型不得生成安装来源。

模型与账户取宿主全局默认，界面明确显示路由摘要，不声称天然等于当前会话选择。辅助分析在精确模型声明支持时优先使用 low 推理档，否则选声明中的最低档；未声明推理能力时不猜参数，不修改宿主全局设置。不另收模型 Key。未配置、登录失效、额度不足、返回格式不合法、限长、超时与取消分别报安全可操作错误，不把关键词结果冒充模型理解。第三方目录文本始终是引用数据，不是执行指令。

索引首批约 10–20 个真实 DSH bundle；固定作者仓库、包版本、提交、兼容声明与文档来源，标明 metadata-only。只读刷新不安装或执行候选代码。不存在的能力不得硬凑。首版不静默启用自定义市场或修改用户 profile。

方案确认后选择实际工作区，通过官方 `uiWorkspace.connectWorkspace` 取得目标会话，保留并核对其精确绑定，再调用原生 `requestDraftInitialization`，始终使用 `clearPreviousDraft:false`。只在 `applied` 后打开目标会话并显示草稿已准备；`preserved`／`blocked` 保留方案并提示处理原草稿或稍后重试，取消、卸载或目标变化时不继续写入。会话消息仍由用户发送。安装交宿主插件管理；首版提供精确安装信息和打开管理入口，不能把自制复选框当宿主授权。组合待真实任务回验。

反馈只在用户点击保存后记录到本机插件数据，包含结果状态、候选与简短说明，最多保留最近 100 条，不自动外发、上传任务或联系作者。需要公开反馈时由用户自行检查和提交 GitHub Issue。
