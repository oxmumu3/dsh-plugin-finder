# 当前工作区流程 · 0.12.0-preview.1

包身份：`@oxmumu3/dsh-plugin-finder@0.12.0-preview.1`。准确目标：官方 Harness `0.2.1-rc.5`、Node `^22.19.0 || >=24.0.0`，四个 SDK peer 均为 `0.2.1-rc.5`。发布与实际场景覆盖以对应发行回执为准。

## 首页：只需交代目标

首页只有一个需求输入，同屏提供一张具体建议；精选和六类插件商店保留在下方。产品介绍占自己的正常布局空间，可以关闭，不覆盖输入或推荐。需求与推荐共用对齐轨道和动作尺寸，窄屏按完整模块自然下排，不新增模式 tab。

提交需求后，系统连续理解、核对来源并组织最小方案。原生足够就沿用；一个插件合适就用一个；组合可保留 2–4 个现成插件。只在必要信息、歧义、权限或真实后果需要时请用户判断，旧输入与授权继续沿用。

## 部分现成、部分补齐

混合方案保留 1–4 个现成插件，并列出具体缺失能力与原因。页面区分「计划复用」和「待补齐」，使用户看懂为何需要新能力，但不把这些计划标签当作安装或验证事实。

点「补齐并使用」后，系统沿用原需求，保留现成部分，只把真实缺口交给官方 Creator；没有必答缺项时自动继续创建、受控安装与原任务接续。需要材料或权限时，在同一上下文处理。用户也可主动选择自己的定制方向。

Finder 通过当前 profile 的官方管理器准备精确插件。确认 installed、enabled 与实际 active 后再执行任务；不要求先到插件管理器手动补装。已有来源或版本冲突、状态未知、审批与重启要求保持明确，不自动替换或盲重试。

## 同一个成果继续修改

执行区域优先呈现实际会话、必要审批和可读取的文件预览；能力方案作为次级上下文。用户原目标、来源、修改记录与版本都保留，需要时展开。没有实际产物时只显示真实运行状态，不用模拟界面填补成功结果。

任务、修订、执行请求、工作区和会话保持精确关联。恢复旧记录只观察原关联，不自动再发任务；重复点击、页面刷新或未知发送结果不会被当作重试理由。停止也不撤销已经发生的操作。

会话 completed 仅表示该轮结束；文件内容正确、插件安装、首次可用、组合或缺口真正满足目标，均需要相应证据。原任务未完成时继续补充、恢复或修复，不以创建出一个插件结束用户需求。

## 建议、浏览与数据

没有个性化授权时，建议位显示标明「通用想法」或「本机线索」的具体想法。最近最多三份 Finder 原始需求与目标、产出、约束摘要可一次自愿授权给当前模型；不由此读取其他文件或完整会话。自选范围通过参考信息设置，已有授权在原范围复用，可随时停止。采纳建议才进入真实供给检索与任务执行。

浏览精选或商店中的具体插件，直接查看同一插件的用途与安装状态；合适可在详情安装或启用，不再另生成一份需求方案。浏览与安装本身不调用模型。

原方案、未发送输入、草稿与旧执行关联保留。安装作用于 profile，任务绑定工作区，不混称工作区安装沙箱。集中摘要回传默认关闭，与建议资料授权不同；共创及派生记录只存本机。范围见[数据回传说明](data-sharing.md)。

## 验证与历史

每次发行需独立完成精确 rc.5/SDK 最终包回归、真实官方隔离 Host 安装与停启验证，以及首次安装、混合补齐和原任务产物核对。旧版实跑只支持各自场景，不替代本轮验收或公开版本核验。
