# 安装、首次使用与卸载

本说明对应 `dsh-plugin-finder@0.3.0-preview.2`。包声明支持 DSH `0.2.0-rc.2` 与 `0.2.1-rc.2`、Node `>=22.13`；兼容声明不等于所有环境已经验收。本文说明安装流程，不代表本版原生安装或公网生产链路已经验收；请到 [v0.3.0-preview.2 Release](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.3.0-preview.2) 核对实际附件、校验值与验证记录。

旧 `0.1.0-preview.1` 把候选局限于固定 15 条索引，不符合动态发现要求，已由后续动态发现版本修正。升级时请核对实际启用的是 `0.3.0-preview.2`；旧版本的安装与草稿测试不能替代本版验收。

## 在正在使用的 DSH 中安装

1. 确认 DSH 版本。Desktop 应用和终端里的同名 `dsh` 可能来自不同安装；优先使用该应用自己的原生「插件」页。
2. 从对应 Release 下载 `dsh-plugin-finder-0.3.0-preview.2.tgz`，按发布页 SHA-256 核对文件。
3. 打开 DSH「插件」→「添加插件」，在安装来源中填写：

   ```text
   https://github.com/piggy00544/dsh-plugin-finder/releases/download/v0.3.0-preview.2/dsh-plugin-finder-0.3.0-preview.2.tgz
   ```

   也可填写压缩包在 **DSH 宿主机器**上的完整路径；这不会把浏览器本地文件自动上传到远端。
4. 核对包名、版本、来源及宿主兼容诊断，再按宿主提示确认。原生管理页若不接受该来源，可用下方匹配版本的官方 CLI。
5. 按宿主显示的激活结果操作；需要重启时选择合适时机。打开侧栏「发现好插件」，检查默认模型摘要和搜索来源说明。

本项目发布包包含预构建客户端。推荐结果中的其他候选是独立插件，仍需用户在宿主管理器确认安装；不会因推荐而自动安装。

## 交给 DSH 的自然语言指令

```text
请通过当前 DSH 的原生插件管理能力安装并启用“发现好插件”：https://github.com/piggy00544/dsh-plugin-finder/releases/download/v0.3.0-preview.2/dsh-plugin-finder-0.3.0-preview.2.tgz 。安装到我正在使用的 DSH，不要另建 profile；需要我确认或重启时请提示我，完成后核对侧栏入口。如果当前会话没有安装工具，请给出在宿主插件页安装的步骤。
```

这段话表达安装意图。是否能直接完成取决于当前会话是否开放安装工具以及宿主确认；不承诺所有会话都能“一句话自动安装”。

## 使用官方 CLI

确认 CLI 与目标宿主匹配后，把示例 `your-profile` 替换为实际正在使用的 profile，不要为了安装另建一个与当前应用无关的 profile：

```sh
dsh plugin --profile your-profile add "/absolute/path/dsh-plugin-finder-0.3.0-preview.2.tgz"
```

`--profile` 位于转发给 pnpm 的 `add` 之前。安装进另一个 profile 不会自动出现在当前应用。Desktop 使用受应用管理的保留 profile；普通 CLI 可能拒绝管理它。Desktop 用户优先用原生插件页；命令行操作请依照该 Desktop 随附的官方 CLI 说明，不要绕过保留 profile 或版本检查。

参数依据官方 [打包与安装插件](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/user/develop/basic/publish.zh.md) 和 [CLI 行为参考](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/apps/cli/reference/README.zh.md)；实际帮助与管理器提示优先。

## 第一次跑通

1. 在 DSH 配置可用的全局默认模型。登录或已有 Key 由宿主管理，本插件没有额外模型 Key 输入框；修改后可点「重新读取配置」。

2. 描述具体任务，点击「理解这个需求」，核对目标、输入、产出、约束、能力和搜索词。
3. 点击「确认需求，搜索并推荐」。先看方案、重要前提与所选插件安装指引；完整搜索来源、时间和覆盖统计可按需展开，来源异常会单独提示。新路径按需读取 Awesome 完整第三方目录（npm 与 GitHub-only）及 format-1 补充索引、用户已配置市场和 GitHub topic 补充来源；不受旧固定集合限制。
4. 展开候选资料，核对作者清单、README 来源、版本／提交、使用前提及未知项。资料读到不等于已安装或任务成功；未取到 README、内容截断及版本差异会保留提示。
5. 如需安装候选，复制精确来源并打开 DSH 原生插件页，由用户和宿主确认兼容性、脚本与安装结果。本插件不自动安装推荐候选。
6. 返回方案，明确选择任务工作区并预览草稿，再点击「确认方案，去会话继续」。插件先保存所选任务版本，成功后才准备原生草稿；`applied` 后打开会话，核对草稿与材料后由用户自行发送。插件保存准确的工作区、会话关联，之后「继续原会话」仅打开该会话，不覆盖草稿。
7. `preserved` 表示已有草稿或附件被保留、本次方案没有写入；`blocked` 表示暂不可写。两种情况都保留方案供处理、重试或复制。实际试用后保存反馈；若已明确同意，后续新操作的有界摘要会自动排队回传，无需逐条导出。不同意时只保存本机反馈。想调整就点击「反馈并优化方案」，确认新理解后重新搜索，旧版本不覆盖。反馈是用户自报，不代表插件已通过安装或运行验证。
8. 「新需求」只开始另一个任务；「我的方案」可回看每个任务、版本与反馈。回看不调用模型、不联网重搜。可导出、导入单任务 JSON 备份，导入不会替换正在编辑的任务。旧版已删除的方案只有在存在备份时才能恢复，恢复记录会明确标记来源。

可以从 [README 的通用任务](../README.md#可以观察的三个任务) 开始。任务不需要先说出插件名，也不用为了验证搜索先开放真实业务数据。

可选回传设置不在首次流程中展开，也不是使用前提。想参与匹配改进时，可随时从页头「回传设置」或反馈填写附近的「查看可选回传设置」打开说明，再自行选择是否同意。尚未选择过时，首次反馈保存后可出现一次非阻断提示；本次已保存的记录不会因此追溯上传。明确同意后，新操作会携带所关联需求、方案和反馈的最小摘要及必要插件版本上下文，不批量补传历史事件。完整范围见[数据回传说明](data-sharing.md)。

## 搜索、模型与费用

本插件对索引和 JSON 读取使用 5 分钟内存缓存；宿主市场缓存由宿主管理。来源新增内容可在缓存到期后参与搜索，无需重新打包插件。来源状态会区分实时、缓存、过期、失败与未配置；部分来源失败意味着覆盖不完整，全部来源不可用时报搜索错误。网络失败或 GitHub 限流不等于没有合适插件。

首屏读取配置、本机任务、历史与回传设置，不调用模型。未同意集中回传时，不向收集服务注册或上传；已同意时后台可继续同步当前同意周期内的排队摘要。需求理解和推荐沿用宿主默认模型与账户，模型支持时采用较低推理档（优先 low），不修改全局设置；完整流程通常请求模型 2 次，重新操作或提供方重试可能增加调用。沿用该模型正常额度及计费，不保证等于当前会话选择。原生会话后续发送任务仍正常计费；第三方候选服务可能另外要求账号、Key、授权或费用。

查询词会用于 GitHub 和已配置市场搜索；模型会接收需求、确认后的意图与候选作者资料。此流程需要联网，也不是离线模型推理。完整历史包含需求、各版本理解与推荐、候选资料、主动保存的反馈及会话关联，保存在本机用于接续与备份。明确同意后的集中回传从新操作提取有界摘要，不上传整个备份；回传路径不读取文件、完整会话或模型凭据。摘要清理常见路径、邮箱与凭据格式，不能保证识别所有敏感内容，请勿在需求与反馈中留下不宜分享的信息。

「新需求」不删除历史、草稿或反馈。每任务的业务历史上限为 8 MB UTF-8 JSON，其中预留 1 KB 给恢复来源；达到上限会报错并保留旧版本。集中摘要队列另有每任务 256 KB（256,000 字节）上限；未入队会明确提示，本机业务仍保存，不能视为已回传或必将重试。导出的 JSON 可能含私人需求，分享前请自行检查。集中同步、停止与删除的完整规则见[数据回传说明](data-sharing.md)。

## 常见卡点

| 现象 | 下一步 |
|---|---|
| 仍显示固定 15 个候选 | 核对启用版本，升级到 `0.3.0-preview.2`；旧包不符合动态发现要求。 |
| 未出现侧栏入口 | 在当前宿主插件页核对安装、启用及激活诊断；装入其他 profile 不会出现在当前应用。 |
| 未找到默认模型 | 配置宿主全局默认模型后重新读取；已有某个会话可运行不等于全局默认已配置。 |
| 全部来源读取失败 | 保留当前意图，检查网络并手动重试。不要将该错误当作“生态没有插件”。 |
| 某个来源失败、限流或使用过期缓存 | 阅读覆盖不完整提示；可根据已读来源继续评估，但不能宣称已经搜遍全部供给。 |
| 用户市场显示未配置 | 可以继续使用可用的公开来源；如有团队市场，先在 DSH 原生市场配置，本插件不会代为添加。 |
| README 不可读取或被截断 | 当前前提与输入输出可能不完整，打开来源核对后再决定。 |
| 没有合适候选 | 结合来源健康、查询词和缺口说明判断；本版不穷尽全网，空结果不代表不存在相关插件。 |
| 推荐了已安装候选 | 到宿主插件页核对，已有能力无需重复安装；本版不自动查询安装状态。 |
| 安装或重启后想接着刚才的方案 | 打开「我的方案」，选择任务与版本；已有精确关联时可「继续原会话」。新需求不会删除历史；恢复不等于重新搜索、安装成功或任务已执行。 |
| 模型格式、限长、额度或登录错误 | 按安全提示处理，保留需求后手动重试；重试仍可能消耗模型额度。 |
| 工作区为空或目标已变化 | 在 DSH 添加／核对工作区再明确选择；不会自动换成另一个项目。 |
| 提示已有草稿被保留 | 本次方案没有写入。点击「打开已有草稿」回到该会话，先处理原草稿；也可预览并复制方案。 |
| 提示草稿暂不可写 | 核对宿主会话状态后手动重试，不会自动发送任务。 |
| 反馈保存失败 | 保留说明后重试；未显示成功前不视为已记录，更不代表已回传。 |
| 本机已保存，但集中记录未能入队 | 本机方案和反馈仍保留；这条摘要未确认入队，不能仅凭“待同步 0 条”判断全部回传。按提示检查后重试操作，不把未入队记录当成等待网络重试。 |
| 已同意但仍显示待同步或同步异常 | 点击「刷新同步状态」核对；已入队摘要会在当前同意周期内自动重试。只有“服务端确认收到”才表示收到，不代表安装、运行或任务成功。 |
| 想停止回传或删除已回传记录 | 在「匹配改进与自动回传」操作。停止不回溯删除；删除申请离线时显示待处理，必须等服务端明确确认。 |

## 卸载与升级

在 DSH 原生插件页找到 `dsh-plugin-finder`，按宿主提示停用、卸载或升级。CLI 管理的实际 profile 可使用匹配版本的官方命令：

```sh
dsh plugin --profile your-profile remove dsh-plugin-finder
```

升级时核对旧包已被替换；需要重启或先卸载再安装时遵从宿主提示。升级前建议从「我的方案」导出重要任务。插件的本机领域数据独立于安装包；停用／卸载不代表它们已被删除。本版提供单任务导出／导入，不提供历史永久删除入口。卸载也不代替服务端删除；如需删除已回传记录，请先在插件内申请并等待服务端确认。离线待删除时应保留插件与本机状态，以便重试完成。

集中摘要不会自动成为公开 Issue，也不自动推送给作者。作者侧暂由我们汇总、核对后分享去标识结果。「导出给作者的反馈草稿」只作本机辅助；用户可自行补写、核对并分享。另需公开报告问题时，可到 [GitHub Issues](https://github.com/piggy00544/dsh-plugin-finder/issues) 自行填写版本、步骤及预期／实际结果，分享前检查日志和截图中的敏感内容。
