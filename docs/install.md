# 安装、首次使用与卸载

本说明对应 `dsh-plugin-finder@0.1.0-preview.1`。包声明支持 DSH `0.2.0-rc.2` 与 `0.2.1-rc.2`、Node `>=22.13`。实际验证结果见 [验证记录](verification.md)，兼容声明不等于已完成所有版本的运行验收。

本地隔离验收范围见验证记录。发布包的公开下载、SHA-256 核对及第二个干净 profile 安装／卸载复验结果，以对应 [GitHub Release 的验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.1.0-preview.1) 为准。

## 使用自己的官方 DSH 安装

1. 在准备使用的 DSH 中确认版本。Desktop 的应用版本与系统终端里的 `dsh` 可能来自不同安装；优先使用该应用自己的「插件」页。
2. 下载本项目发布页里的 `dsh-plugin-finder-0.1.0-preview.1.tgz`，按发布页提供的 SHA-256 核对文件。
3. 打开 DSH 侧栏「插件」→「添加插件」，在安装来源输入框粘贴发布包的 HTTPS 下载地址：

   ```text
   https://github.com/piggy00544/dsh-plugin-finder/releases/download/v0.1.0-preview.1/dsh-plugin-finder-0.1.0-preview.1.tgz
   ```

   也可填写已下载压缩包在 **DSH 宿主机器**上的完整路径。该路径指向宿主文件，不是把浏览器本地文件自动上传到远端。
4. 核对包名、版本、来源和宿主显示的兼容结果，再确认安装。若当前版本的管理页不接受压缩包来源，可用下方官方 CLI 方法。
5. 按宿主显示的激活结果操作；需要重启时由用户选择合适时机。看到侧栏「发现好插件」后打开，确认首屏能显示候选数量和宿主默认模型摘要。

安装本项目的预构建 tarball 不需要从 Git 源码构建前端。推荐结果中的其他候选是独立插件；安装它们仍由用户在宿主管理页确认，不会因推荐自动安装。

## 使用官方 CLI

先确认执行的是与目标宿主匹配的官方 DSH CLI，而不是另一个旧版同名程序。下面的 `your-profile` 和压缩包路径都是示例，请替换为自己实际使用的值：

```sh
dsh plugin --profile your-profile add "/absolute/path/dsh-plugin-finder-0.1.0-preview.1.tgz"
```

`--profile` 必须放在转发给 pnpm 的 `add` 之前。它会安装到指定 profile，不会因为 Desktop 正在打开就自动安装进 Desktop。不要新建了另一个 profile 后误以为当前应用已经安装成功。

Desktop 使用受应用管理的保留 profile；普通 CLI 可能拒绝管理它。Desktop 用户优先在原生插件页安装；如确需从命令行管理，请依照当前 Desktop 随附的官方 CLI 说明，不要强行绕过保留 profile 或版本检查。

这些参数依据官方 [打包与安装插件](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/user/develop/basic/publish.zh.md) 和 [CLI 行为参考](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/apps/cli/reference/README.zh.md)。若安装的官方版本行为有变化，以其帮助和管理器提示为准。

## 第一次跑通

1. 在 DSH 设置中配置可用的全局默认模型。登录账户或已有 Key 由宿主管理，本插件没有额外 Key 输入框。修改设置后可点「重新读取配置」。
2. 打开「发现好插件」，描述一个具体任务，点击「理解这个需求」。检查目标、输入、输出、硬约束和所需能力，必要时修改。
3. 点击「确认需求，搜索并推荐」。阅读原生／单插件／组合／缺口方案，展开候选卡查看来源、版本、前提和限制。版本声明相符也需要实际安装与任务核验。
4. 需要安装的候选，可复制精确来源并点击「打开 DSH 插件页」。由宿主检查来源、兼容性和安装结果；候选含安装脚本时，请先查看其说明。不要用更改版本豁免来掩盖兼容失败。
5. 返回本插件，在「任务工作区」明确选择材料所在的实际工作区，预览草稿，再点「确认方案，去会话继续」。本插件连接目标会话、核对绑定并准备普通文本草稿；收到原生 `applied` 状态后才打开会话，不自动发送。
6. 在原生会话核对工作区、材料和草稿，再自行发送任务。若宿主返回 `preserved`，已有草稿或附件被保留，本次方案没有写入；若返回 `blocked`，页面提示草稿正在提交或暂不可写。两种情况都会保留方案供稍后重试或复制。
7. 实际试用后回到本页，选择完成、部分完成或没能完成，主动点击「保存反馈到本机」。只保存最近 100 条，不会自动上传，也不会自动向候选作者发送消息。

首次体验可复制 [README 的三个任务](../README.md#可以直接试的三个任务)。不用为了测试推荐而开放真实业务数据或先安装所有候选。

## 模型与费用

首屏只读索引和模型摘要，不调用模型。需求理解和推荐属于辅助分析：沿用宿主的模型与账户，在模型声明支持时选择较低推理档（优先 low），不修改全局设置。一次完整的需求理解与方案推荐通常发起 2 次模型调用；重新操作、宿主或模型提供方的重试会增加实际请求，调用使用宿主全局默认模型的正常额度和计费。它未必与当前会话的模型选择相同。

点击原生会话里的发送按钮后，后续任务仍按 DSH 配置正常计费。候选依赖的搜索、文档或业务系统等第三方服务，可能另外要求账号、Key、授权或费用；复用 DSH 模型账户不会替用户覆盖这些前提。

## 常见卡点

| 现象 | 下一步 |
|---|---|
| 未出现侧栏入口 | 在宿主插件页确认包已安装且启用，阅读激活诊断；安装到其他 profile 不会出现在当前应用。 |
| 首屏无默认模型 | 去 DSH 设置配置默认模型，再重新读取；已有会话可运行不一定表示全局默认已配置。 |
| 账户、额度或网络错误 | 按页面提示在宿主处理，再手动重试。索引读取成功不代表模型鉴权成功。 |
| 模型返回格式错误或超时 | 保留当前描述或已确认意图，手动重试该步骤；不要把失败后的空白当成没有供给。 |
| 没有合适候选 | 查看缺口说明。首版是小规模固定索引，不是整个 DSH 生态的完整目录。 |
| 推荐了已安装候选 | 首版不查询安装状态。到宿主插件页核对，已有能力无需重复安装。 |
| 安装兼容性失败 | 保留错误和版本信息，回来源核对。不要把修改版本豁免作为普通安装步骤。 |
| 工作区为空或已被删除 | 先从 DSH 添加／核对工作区，再明确选择；本插件不会擅自换成另一个项目。 |
| 提示已有草稿被保留 | 本次方案没有写入，已有内容不会被替换。先处理原草稿，或在本页预览并复制方案。 |
| 提示草稿暂不可写或目标已变化 | 先核对选定工作区和宿主会话状态，再手动重试；页面保留方案，不会自动发送任务。 |
| 显示草稿已准备，但当前会话内容不符合预期 | 先不要发送；核对目标工作区和会话，记录操作步骤并向项目反馈。成功状态来自宿主原生草稿服务，不代表任务已经执行。 |
| 保存反馈失败 | 页面会报错，可稍后重试。未显示保存成功前，不应把它当成已记录或已回传。 |

## 卸载与升级

在 DSH 原生插件页找到 `dsh-plugin-finder`，停用或卸载，由宿主确认处理结果。卸载后侧栏入口、主面板和本插件样式应消失；该行为的实际验证以 [验证记录](verification.md) 为准。

CLI 安装的 profile 可使用同一官方 CLI：

```sh
dsh plugin --profile your-profile remove dsh-plugin-finder
```

需要升级时先阅读新版本说明。启用 HMR 的宿主可能要求先移除旧版本再安装新 tarball，避免直接覆盖正在加载的包；使用宿主给出的步骤即可。停用或卸载不代表宿主一定清除了插件数据，首版没有反馈数据的导出或清空界面。
