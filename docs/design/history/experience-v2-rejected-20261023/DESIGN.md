# Finder 体验重设计 V2

日期：2026-10-23。状态：研究后的交互原型，不接模型、真实历史、安装或 Creator。旧 0.6 HTML 和原生验收记录均保留。本轮先交付可审阅的新体验，生产前端改造仍待用户看过原型。

用户补充的验收目标：第一眼高颜值、有设计感、舒服、一眼能懂；通过排版、比例、层级与细节形成品质，不堆叠花哨元素。用户无需先读教程，就能看出从哪里开始、每一步会得到什么及接下来如何继续。此为目标，当前没有用户测试结果。

## 为什么改

旧版完成了功能收口，却把“极简”变成输入框、等权卡片与折叠字段的排列。它没有帮助新用户形成任务、理解推荐、纠正 AI、接着完成下一步；11 个共创字段又把整理工作交还给用户。宿主主面板可自定义 React/CSS，这些不是 Host 控件能力限制。用户提供的家庭助手参考只代表视觉质量方向，不代表其表单/点选交互已获认可。

研究依据：[本地审计](../../research/experience-design/01-local-audit.md)、[研究综合](../../research/experience-design/03-research-synthesis.md)、[Skill盘点](../../research/experience-design/02-skill-landscape.md)。

## 产品与品牌判断

- 对象：知道自己想完成什么、并不懂插件名或实现接口的人。
- 核心工作：把模糊想法变成一条有依据、可继续的实现路径。
- 角色：有判断力的方案搭档，解释推荐和前提；不扮演全能搜索引擎、插件广告位或未经验证的质量认证机构。
- 性格：清楚、可靠、好奇、不过度热情。品牌由推荐理由、失败时的恢复、持续可修改的方案共同表达。
- 成功表现：用户能用原话开始，能说出为何选这个方案，补一句可改变同一份结果，明确知道下一步会做什么。

## 三个方向的取舍

轻插件市场便于浏览，却要求用户自己拼成解决方案；纯聊天省去配置，但结果容易淹没在消息里。采用“对话推进 + 方案工作台”：入口极简，结果以可读、可改、可继续的成果承接。此取舍适合本次 Finder，不是对所有产品强制聊天。

## 信息架构与交互

### 首页：一个想法，一条路径

页头仅自有品牌、继续记录与更多。主区保留一个自然语言输入，示例是可点的完整需求，不要求先填结构化资料。首页同时可探索猜你喜欢和作者精选：有明确兴趣才显示个性化理由；同一产品只出现一次。默认无信号显示编辑精选，不能伪装个性化。

推荐不是等权包名目录。重点推荐展示用途、可得到的成果、前提和明确入口；其余场景用更紧凑的内容组织。AI 分身、家庭助手、DSH Dot、Dot连接Harness按四个产品组呈现，管理组件不拆成额外产品。

### 查找：原话始终在场

提交进入同一需求上下文。保留原请求和取消动作，前端只展示确知阶段，不画假百分比、不暴露内部思维链。当前原型明确以演示阶段模拟，正式实现仅可映射真实请求状态。停止后保留输入，不让迟到响应改写后来的需求。

### 结果：对话在左，方案在右

桌面采用对话与成果双栏。对话给一句判断与必要的理由；方案区保留目标、匹配依据、前提和一个主要下一步。用户补一句即可更新同一份方案和版本，不用重填六个理解字段。来源与备选可展开，不能用长安装说明、覆盖统计、反馈表淹没下一步。

来源未完成或缓存过期单独呈现，优先恢复检索；不因此断言没有供给。完整已保存结果和未提交编辑分别保留，历史恢复回到原上下文。

### 共创：先有可读蓝图，再补关键未知

用户明确希望定制，或结果尚有缺口时，可在同一对话继续。只询问影响首版的未知；提供选择作为核对捷径，同时能补自己的话。能力、案例和实践按当前问题出现，详细依据按需看，不要求先读完整教程。

方案区逐步变为蓝图：首版范围、输入/产出、数据与权限、验收条件。技术字段按需编辑。修改必须有可见反馈并保留上下文。交接 Creator 时先说明将准备哪个版本的草稿、在哪里继续；原型不冒充实际创建会话。

## 视觉约束

- 画布：浅矿物灰白 #F4F7FA，内容白 #FFFFFF；不是全页无层级留白。
- 主文字：深海军蓝 #172F45；次文字 #536579；边线 #DCE4ED。
- 动作：钴蓝 #245DD8，柔蓝 #E9F0FC；成功提示才用低饱和绿，不用多种高饱和状态色竞争。
- 字体：中文系统无衬线，重视中文可读性；标题 40/32px，章节 22/20px，正文 15/16px，辅助信息 13px。品牌由交互和结构形成，不依靠更换字体冒充设计。
- 布局：宽屏内容约1140px；首页以有重点的编辑式布局组织输入与推荐。结果以对话/成果区承接，窄屏变为同一顺序的单列，输入常驻但不遮挡内容。
- 圆角有层级：输入/重点成果18–22px，小控件8–10px；阴影只用于浮层或强调成果，避免所有内容同样卡片化。
- 如需图标，采用固定版本 Lucide 原始资源并保留许可证；本次原型未引入图标包，使用文字动作、方向符号与自有简单品牌标记。不画占位插画、不伪造产品截图；成果示例使用真正的HTML内容并明确“示例”。
- 动效只解释用户动作、生成状态、方案更新，120–220ms；尊重 reduced motion。正文对比度目标4.5:1，控件常用目标44px，WCAG2.5.8的24px含例外只是最低要求。

## 原型范围与证据

可点击：首页输入/示例、卡片详情与准备场景、推荐偏好、搜索/停止、方案结果、自然语言补充、来源不完整及重试、共创澄清/蓝图/按块编辑、Creator交接预览、历史恢复。所有模型输出与工作区均为演示，不连接真实服务。生成状态不可被当作当前实际进度。

质量检查：桌面/窄屏截图、主要任务与失败路径、键盘输入和焦点、对话补充后的成果更新、历史/未提交内容保留、不重复展示产品、不把搜索错误当供给缺口。自动/代理走查不是用户接受；原生安装、真实模型与外部发送另有验收。

实际走查及边界见 [QA.md](QA.md)。窄屏补充成果与对话的页内往返入口；用户不必先滚过完整对话才能看到方案。
