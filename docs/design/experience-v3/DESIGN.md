# 发现好插件 · 体验 v3（待审原型）

2026-11-09。可点击原型：[prototype.html](prototype.html)（示例数据，不连真实服务）。这是设计提案，尚未实现，也没有用户审阅通过。

## 用户原话（触发本轮）

> 我感觉我们现在的交互特别丑，非常不用户友好，因为这是门面嘛。我一般做分享的时候，其实最好的价值就是截图分享，但是你这个做得太丑，都没有办法截图了。
>
> 比如现在对话框上显示的“创造经验已开启”，说实话我也没太看懂是什么意思。开启了之后是什么意思？它的用法是什么？一旦开启了“创造模式”，这个经验是已经自动注入了，还是用户需要手动选什么东西呢？完全看不懂。
>
> 整体的交互要非常流畅地过一遍，做到用户友好，傻逼一看都懂的那种。

## 诊断（Agent 推导，基于用户截图与源码）

- 进度条用的是内部概念：「创造经验」「已开启」说的是开关状态，没说是谁、在干什么、要我做什么。五个阶段没有序号，「经验 / 关闭」两个链接和「开新窗口接着做」一直挂着，不论有没有卡住。
- 首页把产品承诺（找现成 → 装好跑 → 没有就自己做）藏起来了；创造模式的能力在首页完全不可见，用户不知道它存在，也不知道是自动的。
- 方案页把「方案中的能力」「使用前提」「还有 12 项限制」「查看完整方案」并排，一屏读不出结论；查过哪些插件、为什么不选，要展开折叠区才能看到。
- 三处界面没有统一的身份：面板叫「你的插件专家」，进度条叫「创造经验」，专家会话叫「和插件专家接着聊」。

## 设计决定

1. **一个身份贯穿三处**：都叫「插件专家」，同一个鲸鱼标识。创造模式里是「插件专家陪你做」，不再出现「经验」「开启」这类系统词。
2. **首页先讲清它能干什么**：主标题是用户的问题（想让 DSH 多会点什么？），下面一个输入框，再下面三张卡讲三件事：找现成的（6,563 个社区插件 · 6 大类）、装好跑一遍、没有就自己做（标「已开启 · 自动生效，不用设置」）。精选和按用途逛放到下面。
3. **方案页先给结论**：用户原话 → 一张结论卡（一句话结论 + 两个动作）→ 查过的现成插件（每个一句为什么选/没选）→ 接下来三步 → 注意事项（黄色，只放两条，其余折叠）→ 跟插件专家接着聊。截图就是一张完整的「它帮我想清楚了」。
4. **创造模式只在需要时说话**：
   - 第一次：一张说明卡，回答「这是什么、要不要我设置、会不会打扰我」，五步各带序号；「知道了」「这次不用陪」。
   - 进行中：一行，「插件专家陪你做 · 五段进度 · 第 N 步 · 现在在等什么」，其余收进「⋯」（我的避坑本、这个会话不用陪、以后都不用陪）。
   - 卡住了：琥珀色，「卡住了 · 第 N 步 · 什么问题改了几轮」，这时才出现「开新窗口接着做」。
5. **深色优先**：用户截图都是深色；原型按宿主深色绘制，实现时继续只用宿主主题变量，浅色模式同步验证。

## 与现有能力的对应

| 原型元素 | 现有支撑 | 需要新增 |
| --- | --- | --- |
| 首页三张卡、精选、按用途逛 | 目录快照 6,563 / 6 类、精选 4 个 | 只改界面 |
| 结论卡、接下来三步、注意事项 | plan.title / rationale / steps / limits | 只改界面；限制按重要度取前两条 |
| 每个候选「为什么没选」 | 计划只有整体 rationale | 推荐输出加每个候选一句理由（改模型输出契约，需回归测试） |
| 跟插件专家接着聊、方案已更新提示 | 已发布的专家会话与 finder_plan_update | 只改外观 |
| 创造模式第一次说明卡 | 无 | 记录「已看过」（本机存储） |
| 「这个会话不用陪」 | 只有全局开关 | 按会话关闭（提示段与工具按会话判断，宿主侧已支持） |
| 卡住才出现「开新窗口接着做」 | 已有 blocked 阶段与交接草稿 | 只改显示条件 |
