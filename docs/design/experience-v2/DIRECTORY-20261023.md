# Finder 目录重设计：从技术索引到用途浏览

用户已明确授权在这里继续设计、打磨，无需重复风格审批。当前preview.7的层级和品质未获认可，重点是“按用途找插件”。本轮沿用单工作区的真实使用/创建契约，不改模型和执行后端。

问题：18条每条先呈现仓库名与作者，再让人从技术说明中找用途；每条重复两个链接。三列窄栏让用途、配置、版本挤在相同位置。改变间距和边框不能解决这个信息顺序。

选择：两列用途分类，每类三个轻量条目；小屏一列。首页选定18条使用人工策展的用途标题，原插件名称与作者保持来源身份，必要限制在相关条目旁可见。只保留“查看方案”这一主动作，直接沿用startCommunityPlugin，不新增详情中转。来源链接通过插件身份本身表达，不再重复“作者页面”。分类标题处可看全部及准确数量。全量页保持搜索/筛选/分页，实际简介可完整阅读。

比较过：继续三列技术条目会保持现有阅读负担；横向滚动或只显示一个类别会隐藏用户要求的六类样例；18张大图卡需要没有依据的图片且占空间。采用“用途标题—来源身份—必要前提”的轻量行，保留六类×三条可扫读供给。

视觉方向：清楚、稳妥的工具目录。与需求输入相比降低目录动作的颜色重量；用分类间距和稳定阅读轴建立分组，不堆卡片。画布、边框、文字和动作使用宿主主题变量；默认白、浅灰、深墨、灰与单一蓝色动作。中文系统无衬线，章节22、分类18、用途15、来源12.5–13px；点击目标44px以上。分类有少量语义线图标，条目不伪造Logo。动效仅主动状态反馈、尊重减少动效。

首页上半部与精选一并检查比例，不以只改目录完成整页层级。输入最大重心，推荐是一个简洁想法；精选与目录有不同组织，四个精选不再像四块同等重要的大灰板。浏览区域不出现额外模式tab。

验证：当前真实长名称/作者/限制；6×3，分类24条、搜索空态/返回/分页；选中精确来源与原需求不丢；键盘与窄窗；在真实渲染截图中至少自审一轮再交候选。HTML是有界演示，不宣称模型或安装；用户对美感的最终判断不能用自动测试代替。

本轮输出保留旧原件和对比图，候选未验证前不覆盖当前Desktop安装。公开源码参考另存研究笔记，不因借鉴引入其框架、遥测、安装脚本或复杂tab。

## 截图复核后的第二轮修正

- 原浅灰实底操作重复成一列视觉块，改为常显的文字动作与箭头，仍保留44px点击区；分类明确为“查看全部 + 数量”。
- 用途标题16px，前提13.5px，来源12.5px。来源名与作者有清楚分隔；长包名自然折行，实际选择始终传完整ID。
- 完整目录不再重复两遍仓库名，也不展示内部来源枚举“tools”等；名称、完整目录简介、作者来源、查看方案保持分层。
- 响应式以Finder根面板作为CSS容器，不依赖宿主整个窗口。1280px窗口内只有700px宽面板时，需求、精选和目录均能变成单列。精选详情的旧viewport规则也在V2层补齐。
- 纠正基础样式覆盖段落margin的问题，让搜索结果数、用途前提、来源之间保持实测间距。

## 后续目录设计的复用检查

先用真实名称、真实前提和真实空态排版，再做视觉调整；有数据才展示评分、热度与安装状态。首页每条先回答“帮我做什么”，进入完整目录后仍可核对原身份与来源。一次动作直达当前任务，不为信息分层新增必经详情页。

源码参考、可运行HTML、实际截图和宿主能力分别验证：源码可说明组织方法，不能证明视觉品质；截图可说明布局，不能证明真实插件已经安装运行。美感与产品接受度仍以用户反馈为准，测试不替代这一判断。本轮具体验证见QA-20261023.md。
