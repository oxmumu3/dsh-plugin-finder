# Finder 当前工作区体验

2026-10-23。当前入口为 [index.html](index.html)。这是与生产界面共用组件的离线有界演示，供审阅动线和页面状态，不代表真实搜索、执行、创建或安装已经通过。

## 已采纳的用户修正

完成一个功能或步骤，交互必须极简、动线极清楚；不用额外解释，用户看完就知道下一步做什么、为了什么。已否定的 click-next、交接预览、复制到项目、把用户送到 Creator 的流程已从主路径删除。底层若需 Creator，由执行控制器内部使用。

旧 HTML、设计说明和原 QA 已逐字节归档到 [旧版目录](../history/experience-v2-rejected-20261023/ARCHIVE.md)。旧 QA 的浏览器结果只适用于该归档，不能用来证明当前版本。

## 当前主路径

| 页面 | 用户能直接做什么 | 同页得到什么 |
| --- | --- | --- |
| 首页 | 左侧说需求；右侧直接开始一个场景 | 自动理解和查找，不先填表或选路线 |
| 右侧场景 | 点“开始这个需求” | 沿用完整场景约束开始查找；卡片只写一条简短用途 |
| 分类目录 | 浏览用途样例，查看某类全部、搜索或点“查看使用方案” | 保留原输入，核对所选作者来源，再接使用流程 |
| 结果 | 点“使用这个方案”，或“创建自己的插件” | 在当前工作区执行，不出现复制、预览和交接门槛 |
| 创建 | 查看简短范围、用法和约束；缺项点选一次 | 选项立即更新方案，随后“开始创建” |
| 执行 | 看真实状态、处理必要审批、继续说话 | 结果和后续交互留在当前页面；只有一个输入区和停止动作 |
| 查找或执行失败 | 看原因，直接重试 | 原需求、方案和修改保留；来源不全不等于没有供给 |

首页右侧无信号叫“试试这个”，有真实本页兴趣或已保存演示方案才叫“猜你喜欢”，并说明依据。精选始终为作者策展，不因为兴趣改变栏目含义。2026-10-23用户新增分类浏览要求后，在精选下面增加“按用途找插件”：六类各三个，点查看全部在同一区块展开；没有新增全局tab。

结果使用单列。原请求与模型理解保留为短摘要；主要区域显示方案与直接动作，不把完整对话和方案并排重复。新需求正在查找时隐藏上一任务的理解、创建方案和版本，直到新结果返回。完整来源、备选、历史和详细字段编辑放在折叠区域。

## 视觉与可读性

沿用生产界面的浅灰画布、白色成果区、海军蓝文字与钴蓝动作色及宿主主题变量。首页左输入、右单个场景，底部精选；窄屏按同一顺序纵向排列。结果最大宽度 880px，原话、动作、过程和补充保持在同一阅读轴上。短场景描述表达用途，真实开始时仍携带完整约束。

## 组件与演示边界

主页面直接导入 `src/experience-view.js`、`src/featured-view.js`、`src/featured.js`、`src/featured-catalog.js`、`src/community-view.js` 及社区元信息，样式来自 `src/client-style.js` 与 `src/experience-style.js`。构建入口为 `preview-entry.jsx`，通过 `scripts/build-experience-preview.mjs` 将 React、React DOM 和组件打包进单个 HTML。主路径没有第二套 HTML 状态实现。

`preview-controller.mjs` 仅模拟明示示例。它不导入生产服务控制器，不访问模型、文件或宿主，也不会创建真实会话或安装插件。CSP 禁止网络连接；进度与结果持续标为演示。自由输入不在白名单时只保留原话；未知或否定式补充不被当成已理解的方案变更。

演示使用独立存储键 `dsh.plugin-finder.current-workspace-demo.v1`。不读取、清除或改写旧原型键及真实 Finder 数据。原型记录、历史和替换前输入仅保存在该键中；页面重新打开不会自动恢复后台执行。
