# 集中摘要自动回传说明

适用于 `dsh-plugin-finder@0.3.0-preview.1`，当前告知版本为 `2026-10-20-v1`。本文说明数据处理与控制方式，不代表本版原生安装或公网生产链路已经验收；实际验证范围见对应 [Release 记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.3.0-preview.1)。

## 由你明确开启，默认关闭

这是一项可选设置，不在首次找方案流程中自动展开，也不是使用前提。可随时从页头「回传设置」或反馈填写附近的入口，打开「匹配改进与自动回传」说明，再选择「同意并自动回传」或「暂不同意」，没有预勾选。未同意时，不向集中收集服务注册或上传摘要；找插件、宿主模型请求、本机历史与反馈仍可正常使用。

尚未选择过时，首次反馈保存后可出现一次非阻断提示，用户可关闭或查看设置。本次已保存的记录不会因之后开启设置而追溯上传；不会因选择同意而承诺作者一定修改插件、提供通知或产生具体使用收益。

明确同意后，只有**同意之后开始的新操作**生成集中记录并自动排队同步，无需每次另点发送或手动导出。新操作会带上所关联需求、方案的最小摘要及必要插件版本上下文，包括在旧方案上新保存反馈或提交调整意见的情况；不会为此批量补传旧需求、旧方案或旧反馈事件，也不会把单任务 JSON 备份整体上传。

## 回传哪些内容

我们用这些记录分析用户需求与插件供给的匹配、方案选择、卡点和用户自报结果，并为相关创作者整理去标识汇总。

| 内容 | 回传范围与限制 |
|---|---|
| 需求理解 | 已确认目标的有界摘要、能力与约束；不直接发送原始需求字段。 |
| 方案 | 原生能力／单插件／组合／缺口类型，以及标题、理由和步骤摘要。 |
| 候选与选择 | 最多 8 个候选的包名、精确版本／提交、公开 GitHub 仓库、来源类型，以及模型推荐和用户选择状态。 |
| 主动反馈与调整意见 | 有界说明摘要、用户选定的完成／部分完成／受阻状态，以及所关联版本。 |
| 会话接续 | 草稿准备结果，例如写入成功或保留已有草稿；不包含草稿正文、工作区路径和会话内容。 |
| 关联与诊断 | 事件类型、时间、客户端与宿主版本，以及每次同意周期内的匿名关联标识；不直接使用本机任务、版本或会话 ID。 |

回传路径不读取文件、完整会话或模型凭据。不会上传整个任务备份、作者 README 正文或原生会话草稿正文。收集端采用约定字段校验，不接受任意附加字段。

摘要在发送前清理常见路径、文件名、邮箱、链接、号码及凭据格式；识别到部分明确的凭据赋值时会省略整段。**这是启发式清理，不能保证识别所有敏感内容。** 业务秘密、未识别的个人信息或不常见凭据仍可能出现在摘要里，请勿在需求与反馈中留下不宜分享的信息。

找方案本身另有网络请求：查询词会用于插件来源搜索，需求、确认后的意图及候选资料会发送给 DSH 配置的模型，沿用宿主提供方与日志规则。关闭集中回传不会把这些正常功能变成离线处理，也不会改变模型额度与计费。

## 哪些状态可以证明收到

插件在本机保存业务历史，再自动处理已同意的摘要队列。同步设置中可手动点击「刷新同步状态」：

- 「待同步」表示摘要已入队，还未取得服务端接收确认；当前同意周期内，网络失败会自动重试，重启后仍可续传该周期的待发送记录。
- 「服务端确认收到」只表示收集服务已确认接收这些事件；重复投递按事件标识处理，不当成新样本重复计数。
- 「同步异常」表示需要核对网络或记录状态，不能当成回传成功。页面不会因为本机保存成功就声称服务端已收到。
- 「本次集中记录未能确认入队」与网络排队不同：业务历史仍保存在本机，但这次摘要没有确认进入可发送队列，不能仅凭“待同步 0 条”断言全部已同步，也不能把它当成只需等待的记录。

每个本机任务的集中摘要记录上限为 **256 KB（256,000 UTF-8 字节）**；达到上限或投影失败会提示未能入队，不影响本次业务历史保存。业务历史另有每任务 8 MB 上限；两种容量与失败提示不同。已确认发送的事件仍占用本机任务的集中摘要记录空间，因此不是无限增长的日志。

## 停止、重新同意与删除

「停止回传」关闭后续收集与上传，结束当前同意周期，并取消仍在进行的发送。已经发出的请求可能已被服务端接收；停止操作不会回溯删除这些记录。之后重新同意会开始新周期，旧周期未发送队列不会因此重新变成可发送记录。

要删除收集服务中的相关记录，请另点「删除已回传记录」。这会停止回传并申请删除本安装可关联的相关同意周期记录：

- 服务端明确确认删除后，才显示删除确认时间；未发生服务端注册时会说明没有已回传记录。
- 离线、超时或失败时显示「删除申请待处理」，不表示删除已完成。保持本机状态和插件可用，以便自动重试，也可稍后手动刷新或重试删除。
- 删除申请未完成前，不开启新同意周期。删除服务端记录不会删除「我的方案」里的本机历史或个人导出备份。
- 停用或卸载插件不等于删除已收到的服务端记录；如需删除，请先在插件内申请并核对确认。

服务端事件保留 **90 天**，到期清理；用户可在此前主动申请删除。接收服务地址与告知版本展示在插件设置中，便于在同意前核对。

## 如何使用创作者反馈

安装状态、运行结果与插件首用尚未自动验证。反馈属于**用户自报**；“任务完成”“方案被选择”“草稿已写入”和“插件安装成功”是不同事实，不能相互替代，也不自动把任务结果归因于某个插件。集中记录是参与并同意回传的样本，不能直接代表全体用户或生态使用量。

作者侧暂由我们对集中结果汇总、核对后分享去标识内容；本版不自动推送给作者，不自动创建公开 Issue，也不提供作者后台。

「我的方案」中的 JSON 导出／导入是个人备份辅助，可能包含私人需求与反馈原文，请自行保管和检查。候选详情的「导出给作者的反馈草稿」也是辅助选项：仅在本机生成 Markdown，预留可分享场景摘要供你补写、核对并自行发送。两者都不是自动集中回传的必经步骤。
