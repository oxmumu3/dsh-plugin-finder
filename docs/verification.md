# 首版验证记录

核对日期：2026-10-20。版本：`0.1.0-preview.1`。这是第三方 Preview，验证范围与正式任务成功分开记录。

## 环境与代码检查

- 官方 DSH `0.2.1-rc.2` Desktop 随附 CLI / Web Host，在独立 `DSH_HOME` 中安装、启动。声明支持的 `0.2.0-rc.2` 未做本轮运行验收。
- 最终构建后的 `npm test`：66 项通过、0 失败。覆盖目录来源、检索与版本/Node/Key 过滤、模型终止/限长/账户错误/取消、结构校验、固定插件能力引用、原生目标会话绑定与草稿状态、并发和本机反馈存储。
- `npm run build` 生成原生 ModuleLoader 客户端，React 由宿主提供。页面只增加自己的侧栏入口、主面板和局部样式。
- 测试不安装、不执行目录中的第三方候选；没有发送原生会话消息。

## 真实索引

- 人工白名单中的 15 个原生 bundle 完成只读来源刷新，固定到包版本和 commit。最近刷新 15/15 成功、0 错误。
- 11 条仅核对元数据与有限主入口存在性；2 条需要 Git 源码构建确认；2 条固定源码缺少运行产物且没有相应 prepare，默认排除推荐。

## 真实宿主与模型

原生页面已经在官方隔离 Host 中加载，显示真实索引、宿主模型与实际工作区列表。需求理解与推荐使用宿主的 `deepseek-account / deepseek-flash`，没有另外输入模型 Key。仅发送合成任务文字和公开候选摘要。

辅助分析按精确模型元数据选择较低推理档，不改变宿主默认模型或设置。此前沿用 Max 的推荐曾出现截断；测试驱动补齐了限长提示与轻量档选择。不能把一次模型响应当作推荐准确率或插件任务成功率。

## 本地原生交互验收

- 在官方 `0.2.1-rc.2` 的独立 Web profile 中，从原生侧栏打开本插件，完成真实模型需求理解、六个意图字段确认及方案推荐。成功返回单插件方案，候选为 `dsh-data-quality`。
- 明确选择合成工作区 `sample-workspace` 后，通过 `connectWorkspace`、保留的精确会话绑定和原生草稿服务接续。在目标会话的原生 `contenteditable` 中读回完整 4366 字草稿，包含原需求、固定来源及限制。草稿未发送，候选插件未执行。
- 随后手动把该原生草稿改为 `synthetic-user-draft-marker`，再次接续返回 `preserved`；读回原标记未变。本次方案没有覆盖已有文字草稿。
- 在插件 UI 主动保存一条「部分完成」合成反馈，从隔离 Host 的 `storages/plugin_finder.json` 读回 1 条记录，结果、候选 ID 与补充说明和输入一致。没有向作者、项目或其他第三方发送反馈。
- 验收完成后停止专用测试 Host，并移除临时凭据副本；用户常用 DSH profile 未修改。

这些记录证明本次合成任务的本地推荐和草稿接续路径，不代表第三方插件已安装、任务已完成、组合可用或已有外部用户反馈。
