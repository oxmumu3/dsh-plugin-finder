## 可选集中摘要回传（0.3.0-preview.1）

独立 Cloudflare Worker + D1 已部署。公网验收使用 `environment=test` 的合成需求，通过实际生产 service/history/sender 类完成：未授权零请求；授权后生成需求确认、方案生成、方案选择、任务自报反馈四条新记录；模拟首次发送失败后，重建客户端并自动补发、收到四条 ACK；管理接口读到关联需求、方案与插件精确版本，并聚合出一次候选、推荐、选择和 partial 自报；正式统计排除这些合成记录。停止后新反馈仅留本机，重新开启不补旧记录；删除取得服务端确认后，管理接口读回测试记录为零。另有收集端公网探针验证重复事件去重、跨安装事件冲突、非管理员拒绝、删除后的旧令牌写入拒绝。

这些是合成链路验收，不是外部用户同意、真实使用量或作者改进结果。未替真实用户开启回传。授权设置默认折叠，不拦首次找方案；用户可在反馈区或设置中自行开启。安装与运行状态仍未知，反馈仍为用户自报。当前宿主安装、历史保护和发布包读回以本版 [Release](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.3.0-preview.1) 的实测记录为准。

## 旧版范围错误与本版修正

旧 `0.1.0-preview.1` 将推荐限制在固定 15 条索引里，不符合动态发现要求。旧版的安装、模型与草稿验收验证的是当时那条有限路径，不能算作新版动态发现端到端验收。

本版生产入口已改为 `createDiscovery`：读取外部来源，再把当轮候选及作者资料交给模型。它不加载旧静态集合来限定候选，也不会在来源失败时悄悄回退到旧集合并宣称已完成搜索。仓库遗留静态资料仅用于历史研究与测试参考。

## 完整社区目录修正（0.2.2-preview.2）

此前只读取 format-1 索引遗漏了该社区目录的 GitHub-only 半边，GitHub topic 补搜不能保证补回。当前增加动态 plugins.json 主源，按需求检索全部可安全解析记录，再锁定 GitHub 提交和子目录核对实际包清单；有 npm 标记但缺版本等格式索引前提的记录也可从仓库解析。该修改不证明全网穷尽覆盖，也不把原始条目都算作可安装插件。

新增覆盖回归包括完整源中的 GitHub-only、monorepo 分支／子目录、缺 npm 元数据、恶意路径、来源失败、身份冲突、Key 筛选后的候选补读、作者资料与总体时间预算，以及覆盖统计透传。原生升级与真实资料库复测结果将在完成读回后写入本版 Release。

`0.2.2-preview.2` 当时只提供给作者的本机 Markdown 草稿，安装与运行状态默认未知，没有集中收集后台。`0.3.0-preview.1` 新增明确同意后的集中摘要路径，详见上节与[数据回传说明](data-sharing.md)；本机导出保留为辅助，不自动联系作者或验收首用。

## 仍需分开判断的结果

- 读取作者资料与候选安装成功、功能运行、任务完成、组合衔接是不同证据；本版不会自动安装推荐候选。
- 所列来源未覆盖的插件、未读取的排序后候选、私有仓库／内部系统，以及不同宿主／平台／模型仍有覆盖边界。
- 缓存过期、网络失败或限流不等于生态没有供给；部分失败必须保留覆盖不完整提示。
- 原生草稿准备不代表发送或执行；附件组合、长期稳定性和实际业务任务结果需要各自验证。
- 本机合成反馈不计作外部用户反馈、使用量、留存或成功率。

生态里已有 `dsh-find-plugin` 等检索工具。后续比较应围绕同一任务：理解是否准确、能否找到任务所需供给、作者资料是否支持分工、安装／首次使用卡点是否减少，以及接续后是否完成任务，不以“首创”或目录规模代替效果证据。
