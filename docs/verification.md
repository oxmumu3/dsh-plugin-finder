# 动态发现 Preview 验证范围

核对日期：2026-10-20。版本：`0.2.0-preview.1`。这是第三方 Preview；源码路径、在线检索、原生安装、模型推荐、会话草稿、首次使用及外部反馈是不同的证明状态。

## 旧版范围错误与本版修正

旧 `0.1.0-preview.1` 将推荐限制在固定 15 条索引里，不符合动态发现要求。旧版的安装、模型与草稿验收验证的是当时那条有限路径，不能算作新版动态发现端到端验收。

本版生产入口已改为 `createDiscovery`：读取外部来源，再把当轮候选及作者资料交给模型。它不加载旧静态集合来限定候选，也不会在来源失败时悄悄回退到旧集合并宣称已完成搜索。仓库遗留静态资料仅用于历史研究与测试参考。

## 当前源码与自动检查范围

- Awesome DSH 第三方 [format-1 索引](https://awesome-dsh-plugin.com/index.json)、宿主已配置市场和 GitHub `dsh-plugin` topic 构成当前发现来源。它们不是全网穷尽检索，也不是官方审核结论。
- 按需求进行有界召回，再读取相关性靠前的作者 manifest 和 README；核对包身份、版本／提交、bundle 声明、兼容前提及来源。只读清单与文档，不安装或执行候选代码。
- 本插件的索引与 JSON 读取有 5 分钟内存缓存；用户市场缓存由宿主管理。保留实时／缓存／过期／失败／未配置和读取时间，README 缺失、截断或版本可能不一致时保留提示。
- 动态发现回归覆盖：旧集合外候选进入推荐、上游新增条目在缓存到期后被发现、来源异常／GitHub 限流、全部来源失败先于模型缺口判断、部分失败提示传到方案、作者资料进入模型、动态候选反馈 ID 验证和原生市场接口读取。
- 原生工作区草稿继续采用 `connectWorkspace`、保留的精确会话绑定与原生 `requestDraftInitialization`，区分 `applied`／`preserved`／`blocked`，不自动发送。

本版集成本机当前任务接续：在 `plugin_finder` 的独立 workflow 表保留最近一个任务的原始输入、意图、候选／作者资料及推荐方案，重新打开时从 bootstrap 恢复；点击「新需求」通过 reset 清除该任务记录。自动本机保存与模型请求、用户主动保存反馈、公开提交反馈是不同数据路径；恢复本身不自动外发、再次调用模型或发送会话消息。原生跨重启恢复的结果单列于 Release。

最终构建及完整测试结果，以对应 [v0.2.0-preview.1 Release 验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.2.0-preview.1) 为准；不沿用旧版测试数作为新版结论。

## 新版实际宿主与发布包验收

一条已完成的合成任务见[完整实跑记录](first-use-case.md)：从未提供插件名的需求，动态发现 `dsh-md-studio@1.2.0`，通过原生管理器安装启用，准备指定工作区的原生草稿，并在右侧预览中实际渲染 Mermaid SVG。KaTeX 原生已支持，本例只把公式正常保留作为回归项。该记录不是外部用户反馈或总体成功率。

新版在真实 DSH 中的安装、动态搜索 UI、宿主模型推荐、安装／重启后当前任务恢复与「新需求」清除、原生草稿读回、已有草稿保留、反馈落盘、候选安装确认和首次使用结果，以及公开 tarball 的 SHA-256／匿名下载／干净 profile 安装卸载，统一以 [v0.2.0-preview.1 Release 验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.2.0-preview.1) 为准。只有实际观察到的项目才可记为通过；本文件不提前宣称通过，也不移用旧版 4366 字草稿等记录。

包声明支持 DSH `0.2.0-rc.2` 或 `0.2.1-rc.2`、Node `>=22.13`。版本声明相符不等于相应版本、平台和模型都已经运行验收。

## 仍需分开判断的结果

- 读取作者资料与候选安装成功、功能运行、任务完成、组合衔接是不同证据；本版不会自动安装推荐候选。
- 所列来源未覆盖的插件、未读取的排序后候选、私有仓库／内部系统，以及不同宿主／平台／模型仍有覆盖边界。
- 缓存过期、网络失败或限流不等于生态没有供给；部分失败必须保留覆盖不完整提示。
- 原生草稿准备不代表发送或执行；附件组合、长期稳定性和实际业务任务结果需要各自验证。
- 本机合成反馈不计作外部用户反馈、使用量、留存或成功率。

生态里已有 `dsh-find-plugin` 等检索工具。后续比较应围绕同一任务：理解是否准确、能否找到任务所需供给、作者资料是否支持分工、安装／首次使用卡点是否减少，以及接续后是否完成任务，不以“首创”或目录规模代替效果证据。
