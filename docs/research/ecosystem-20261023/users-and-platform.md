# Harness 用户规模与平台定位：公开证据核查

核查日：2026-10-23。仅为公开研究，未对用户分布做抽样，也不是 Finder 功能验收。浏览器沿用 ego Space 136 / p1；GitHub 原文另通过公开 API / raw 文件核对。源码引用固定于本次读到的官方 master `687f282e8625c6b8d11ff58211a90524be2e4317`。

## 可以采用的结论

1. **本次已查公开资料未找到 Harness 的绝对用户数、DAU 或 MAU 数值。** 不能由 DeepSeek 整体用户数、仓库 Star、插件目录数、下载次数推算 Harness 用户规模。
2. 官方在 **2026-09-30** 披露过两个相对指标：在使用 DeepSeek 官方 API 的用户中，Harness 按 DAU、日会话等指标是使用最广泛的 coding agent；在通过官方 API 访问模型的 Harness 用户中，约 **60%** 使用第三方插件。原文未给绝对人数、统计窗口、去重方法、样本量或独立审计，不能扩展为整个 coding agent 行业排名，或全部 Harness 用户的插件使用率。[官方长文](https://x.com/DeepSeekHarness/article/2105330281389662575)
3. **“官方只面向开发者”不成立。** 官方首页同时展示日常办公、代码与自建 Harness；Creator 是对话创建或配置插件的实验性能力。源码教程确实需要开发知识，但不能据此推断 Creator 用户组成。[官网](https://www.deepseek.com/harness/)、[官方长文](https://x.com/DeepSeekHarness/article/2105330281389662575)
4. **已有官方提供的市场机制，不等于已有官方统一收录的插件目录。** 当前文档说明实验性“自定义插件市场”需开启、添加索引 URL，且 DSH 不内置索引源；索引内容由第三方提供。2026-09-30 的“建设官方插件市场”是计划表述。不能把社区目录中的全部条目称作官方审核的市场插件。[市场文档](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/user/guide/plugin-market.zh.md)

## “偏开发者”应如何写

可作为观察：手工插件开发文档面向开发者，技术接口较多，README 仍提醒预览阶段兼容性变化；自定义市场也需要用户自行添加可信索引。这些是具体的使用条件与维护负担。

同时必须保留：官方已提供桌面安装包、无需命令行的插件管理、对话创造插件，以及文档/表格/PPT 等日常工作场景。因而“生态技术资料较多”是可核查观察；“官方把 Creator 定位为开发者专用”“普通人不能创作”“多数用户是开发者”均无本次证据支持。界面是否让普通用户看懂并成功完成任务，仍需真实任务和用户观察来判断。

## 面试文章可直接使用的表述

DeepSeek Harness 是仍在预览阶段的开源 Agent 平台，官方同时覆盖日常工作与编程，并已提供通过对话创建插件的 Creator。我查阅的公开材料未见其绝对用户规模；2026 年 9 月的官方披露显示，在通过官方 API 访问模型的 Harness 用户中，约六成使用第三方插件。当前还提供可接入第三方索引的实验性市场机制。我的产品假设是：用户更需要从目标出发，系统自动匹配现有能力，必要时组合或创建，并把任务结果接回来。这个假设需要任务实跑和用户反馈验证。

不要采用的说法：Harness 有某个百万/千万级用户数；官方市场已有 5000/6000 个经过审核的插件；头部与长尾需求各占一半；Creator 官方只服务开发者；Finder 已覆盖或验证这些需求。目录规模另由目录审计报告按来源、时间与去重口径说明。
