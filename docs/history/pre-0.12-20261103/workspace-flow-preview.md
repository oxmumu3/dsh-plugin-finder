# 当前工作区流程 · 0.8.0-preview.1

> 历史阶段记录：下文的安装版本、公开状态和待验收项按各段当时记录保留。当前公开预览版为 [v0.9.0-preview.10](https://github.com/oxmumu3/dsh-plugin-finder/releases/tag/v0.9.0-preview.10)，当前安装与首次使用请以[安装说明](install.md)为准。

本版是尚未公开发布的本地候选。设计目标是：用户说出需求，系统分析并找出方案；找到就在当前工作区用起来，不满足就在原处创建。每一步应直接说明要做什么及会得到什么。

## 首页与主路径

首页以一个需求输入和「帮我找方案」为主。右侧提供一个具体场景，无偏好依据时显示「试试这个」，有本机历史或明确兴趣依据时显示「猜你喜欢」；底部固定放精选插件。历史、来源、反馈和设置放在次要入口。

提交需求后，系统连续理解、搜索并生成最小方案。结果先呈现能得到什么、如何满足需求和关键前提；需要调整时补充说明，旧版本保留。来源异常单独提示，不能把搜索失败解释成供给缺口。

- **方案合适 → 使用这个方案**：在当前工作区创建关联执行会话并提交任务，在本页观察进度和结果。
- **不满足 → 创建自己的插件 → 开始创建**：沿用需求及已知限制，只有真实缺项才请用户补充，由官方 Creator（`cordis`）在同一工作区执行。

复制、预览草稿、选择交接地点和手动发送内部提示都不是主路径步骤。实际授权、安装确认和必要的用户输入沿用官方宿主组件。

## 目标、恢复与结果

当前会话所属工作区或唯一可用工作区可作为可靠目标，系统自动推断；无法可靠判断时才请用户选择。任务、修订、执行请求、工作区和会话保持精确关联，页面显示的执行项目随原关联保留。

重新打开任务会恢复原执行会话，只观察、不重发。重复点击、刷新或其他页面恢复同一记录，不自动启动第二次执行；发送结果未知时也保留原记录，不据此自动重试。历史方案、未发送输入、旧编辑草稿及旧版会话关联继续保留。

用户可以在当前页面处理宿主请求并查看实际结果。会话 `turn_completed` 只表示一轮结束；文件是否正确、插件是否安装、功能是否运行及需求是否达成，都需要相应的真实证据。停止执行也不撤销已经发生的操作。

## 兼容与数据

官方 DSH `0.2.1-rc.2` 支持本版执行入口；`0.2.0-rc.2` 保留搜索和历史，不承诺直接执行。未知或缺少必要服务的宿主应明确提示能力不可用。

本地历史和草稿继续保留，共创及其派生记录只存本机。普通匹配的集中摘要回传仍默认关闭，完整范围见[数据回传说明](data-sharing.md)。安装方式见[安装说明](install.md)。
