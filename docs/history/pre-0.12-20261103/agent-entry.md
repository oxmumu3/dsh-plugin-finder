# DSH 主会话中的插件专家

工程候选 `0.11.0-preview.10`，以官方 Harness `0.2.1-rc.3` 为本轮验证目标。正在真实验收；本文件不是公开发布回执，也不代表外部 MCP/A2A 接入已实现。

用户直接向标准模式交代原任务。当前能力足够时，Agent继续做；缺少满足质量、时限与约束的必要能力时，按需调用 Finder，查现成插件或组合。确有未满足部分时，在当前工作区调用官方 Creator 生成源码，安装后接回原会话。最终仍按原任务的产物验收。

四个宿主工具为 `finder_lookup`、`finder_activate`、`finder_create`、`finder_status`。它们由插件注册并随当前 Agent 的真实可见工具注入路由提示，不要求用户去工作台再次描述或复制交接。第一次安装、插件 Host 代码和安装脚本仍遵守宿主当前授权与审批；搜索结果不新增权限。

请求身份来自宿主的主会话与注册工作区，模型不能自报用户、会话或安装地址。每请求独立持久历史与方案指针，原 Finder 工作台历史、草稿、主动机会授权和回传同意不迁移。请求里的必要上下文经现有模型服务处理，不默认读取整个项目、私人会话或浏览记录；Agent 请求不继承工作台的集中回传授权。

现成方案只准备服务端核对过的精确来源和版本，未知结果按原回执回读，不盲重装。创建使用官方 `cordis` 受管子任务，只传有界规格；子任务保持原生权限限制，只新建与测试工作区源码，不安装或发布。父 Agent 的受控安装阶段将已验证源码字节归档到工作区新建的 `.finder-install-*` 目录，以精确本地制品安装并回读 active。保留这些归档与源码便于恢复和追溯；不要将它们误作已发布插件。

创建状态恢复只观察已绑定的原子任务，核对宿主目录、原始规格及结构化完成证据。证据不足或后续已改任务时保持未知，不猜产物地址或重复委派。正常在工作区内切换子目录不改变请求归属；跨工作区读取、安装或恢复被拒绝。profile 内插件安装会影响其他会话，不能把工作区绑定当成安装沙箱。

来源失败、覆盖不足、适配未知、权限不足、真正的具体缺口分别记录。找到候选、安装 active、Creator轮次结束与原任务完成是不同事实。真实实跑结论需以相应验收记录为准；本版尚未证明任意插件、所有组合、外部客户端或多租户服务可用。

生成产物校验或首装应用明确失败时，主 Agent 可在原 request 中通过 `finder_create.feedback` 发起有界修复，最多两次。每次保留旧子任务结果、源码地址、安装回执和失败状态，以新的受管 Creator 子任务在独立目录、包名、运行身份与数据目录中修复，接回原任务；运行中、结果未知、额外审批或必须重启不会被当作代码缺口盲重派。已知 SDK 错误只传已核服务名的结构化提示，不把原始诊断或私有文本交给模型。

新生成制品首次安装前记录此前不存在的证明；仅对本请求该证明完整、精确来源和版本仍匹配且未运行的旧失败包，在新包实际 ready 后执行可逆禁用，保留安装、源码和数据。旧版本缺少证明的包不自动退役；退役结果未知只观察，不重复变更。profile 管理器没有来源 CAS，此流程不声称对外部并发编辑提供原子覆盖保证。
