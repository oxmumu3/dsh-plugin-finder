# 发现好插件 · DSH Plugin Finder

[安装说明](docs/install.md) · [一次完整实跑](docs/first-use-case.md) · [两天对照实验](docs/experiment.md) · [验证范围](docs/verification.md) · [本版发布与验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.2.2-preview.2) · [反馈](https://github.com/piggy00544/dsh-plugin-finder/issues/new?template=feedback.yml)

在 DeepSeek Harness 里描述要完成的事，确认理解，动态搜索插件来源、阅读作者资料、拼出最小方案，再带着未发送草稿回到原生会话。

**当前版本为 `0.2.2-preview.2`。** 本版补入完整社区目录的 GitHub-only 与仓库子目录供给，保存并展示来源覆盖和有界核对过程；「我的方案」、历史版本与反馈继续保留。动态来源检索自 `0.2.0-preview.1` 起提供；固定 15 条索引不参与生产推荐，也不会在联网失败时替代搜索。

## 从哪里发现插件

- **Awesome DSH 第三方目录**：按需读取 [完整目录](https://awesome-dsh-plugin.com/plugins.json)，检索 npm 与 GitHub-only 记录；[format-1 市场索引](https://awesome-dsh-plugin.com/index.json) 作为补充。它是第三方来源，不是 DSH 官方审核目录。
- **用户已配置的 DSH 市场**：通过宿主原生市场能力搜索已有源；未配置就明确显示，不自动添加或更改市场源。
- **GitHub `dsh-plugin` topic**：按需求进行有界补充检索，帮助发现其他候选仓库。

完整目录的记录先按任务匹配，不需要每个作者向我们单独申请加入名单。召回后，在 24 条候选、全轮 45 秒、每候选 8 秒的预算内继续核对至最多 6 个候选；Key 前提不满足的条目不会先占满候选槽。会对相关性靠前的候选读取作者包清单和 README，核对包身份、版本／提交、bundle 声明、兼容前提及安装来源，再把有界作者资料交给宿主模型理解。README 未读到、内容截断或版本可能不一致时，会保留提示；作者声明不等于功能已经验收。

本插件的索引与 JSON 读取使用 **5 分钟内存缓存**；用户已配置市场的缓存由宿主管理。页面展示本次来源、查询时间及实时／缓存／过期／失败状态，以及来源记录总数、npm／GitHub-only、匹配、已核对和未核对数量；跨来源记录会重叠，不能相加当独立插件数。部分来源失败时说明覆盖不完整；全部来源不可用时报搜索错误，不把失败包装成“没有插件”。缓存到期后可看到源内新增内容，不需要为每个新增插件重发安装包。

这仍是所列来源内的动态检索，不穷尽整个网络。目录条目数、GitHub 热度或候选数量都不是使用量、推荐质量或任务成功率。

## 从检索走到可用方案

生态里已有 `dsh-find-plugin` 等检索工具。本项目把它们作为检索基线，在其上衔接：

1. **确认用户意图**：把任务拆成目标、输入、产出、约束、能力和搜索词，允许用户修改。
2. **理解候选资料**：说明作者声称支持什么、需要哪些账号／环境、哪些信息还未知。
3. **确认最小方案**：允许原生能力够用、单插件、最多两个插件的组合或明确供给缺口，说明每一步的输入输出和分工。
4. **原生会话接续**：明确选择工作区，核对目标会话并准备普通文本草稿，由用户检查和发送。

额外价值是否成立，需要和用户直接搜索、现有检索插件及实际任务结果比较，不以“首创”或目录规模代替验证。

本插件只在宿主侧栏增加自己的入口和主面板，保留原生会话与工作区。推荐候选的安装交给 DSH 原生插件管理器确认；本插件不自动安装候选，也不自动提交或执行会话任务。

## 安装与首次使用

包声明支持 **DSH `0.2.0-rc.2` 或 `0.2.1-rc.2`**，Node `>=22.13`。这是兼容声明，不等于所有环境均已验收。新版安装、原生 UI、真实模型、首次使用和公开下载结果，以 [v0.2.2-preview.2 Release 验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.2.2-preview.2) 为准。

下载 `dsh-plugin-finder-0.2.1-preview.2.tgz`，在正在使用的 DSH 原生插件页安装并核对来源；也可使用匹配版本的官方 CLI，详见 [安装说明](docs/install.md)。本项目不要求另开独立模型账户或填写新的模型 Key。

也可以把下面的话交给 DSH。能否直接安装取决于当前会话的工具与宿主权限，这不是已经验证的“一句话自动安装”承诺：

```text
请通过当前 DSH 的原生插件管理能力安装并启用“发现好插件”：https://github.com/piggy00544/dsh-plugin-finder/releases/download/v0.2.2-preview.2/dsh-plugin-finder-0.2.1-preview.2.tgz 。安装到我正在使用的 DSH，不要另建 profile；需要我确认或重启时请提示我，完成后核对侧栏入口。如果当前会话没有安装工具，请给出在宿主插件页安装的步骤。
```

安装后描述任务，点击「理解这个需求」，核对六个意图字段，再点击「确认需求，搜索并推荐」。先阅读“本次搜索”的来源状态，再看方案与候选资料；需要安装的候选仍由用户在宿主管理页确认。选好工作区后准备草稿，实际任务由用户在原生会话发送。

本版会在本机保存每个任务与其历史版本，包括输入、理解、候选资料、方案、主动保存的反馈和原生会话关联。「新需求」只切换到空白输入，旧方案仍在「我的方案」；反馈后可选择「反馈并优化方案」，确认新理解后重新搜索，旧版本仍可回看。历史回看和继续原会话不调用模型、不重新注入草稿。可导出、导入单个任务的 JSON 备份；备份可能含私人需求，分享前请自行检查。旧版尚存的当前任务会迁移；已经删除的记录需要已有备份才能恢复。

## 可以观察的三个任务

```text
把一批 PDF、Word、Excel 和 PowerPoint 文件转成可供 Agent 阅读的文本，优先本地处理。请动态搜索相关插件，核对作者的格式支持、安装前提和额外账号要求，再给最小方案。
```

```text
我想在 DSH 中预览 Markdown 里的 Mermaid 流程图和 KaTeX 数学公式。请搜索相关插件，说明哪个覆盖主要需求、需要哪些宿主能力，以及开始使用的步骤。
```

```text
我想按天保存记事和待办，并在月历里回看每天的日志。请找有作者资料支持的插件，区分已声明能力和未验证部分，再把方案带到我选定的工作区。
```

观察任务是否理解正确、是否召回合适候选、作者资料是否支持推荐、安装／首次使用是否卡住及草稿是否进入正确工作区。任何任务都可以得到缺口或不确定结论，以上不是成功保证。

## 一期如何记录并给创作者反馈

每个本机任务保存原始需求、方案版本、候选精确版本／提交、选择理由，以及用户主动保存的结果反馈。安装、运行与插件首用结果尚未自动核对；任务完成不自动归因于某个插件。

候选详情中的「导出给作者的反馈草稿」生成本机 Markdown，包含该插件在此任务中出现的版本、是否被方案选中和任务自报结果。完整需求、反馈原文、会话标识和本地路径不自动写入；用户填写可分享的场景与原因摘要、检查脱敏后自行发送。不会自动联系作者。记录分散在各用户本机，本项目没有跨用户收集后台，也不会声称已经积累全体用户数据。

## 创作者如何被发现

无需为每个插件向本项目申请加入固定名单。现有第三方精选源、用户原生市场和 GitHub topic 都是供给入口；公开仓库可使用 `dsh-plugin` topic，并在名称、介绍和 README 中清楚说明解决的任务。

提供可安装的 DSH bundle、精确版本及运行产物，在 README 写明输入、输出、账号／Key／系统前提和第一次使用步骤，有助于让推荐有据可查。自定义市场由用户自行配置，第三方精选库的收录由其维护者管理。本项目按任务进行有界检索与资料读取，不保证每次召回所有相关插件或固定排名。

如果资料被误读、来源不可读或漏掉了适合的插件，可通过[公开反馈](https://github.com/piggy00544/dsh-plugin-finder/issues)提供可公开的任务、仓库、精确版本及预期行为；不需要提交私人会话或业务文件。

## 模型、数据与边界

首屏只读取配置、本机任务与历史，不调用模型。需求理解和方案推荐沿用宿主全局默认模型与账户；模型声明支持时，辅助分析使用较低推理档（优先 low），不修改全局设置。完整流程通常请求模型 2 次；重新操作及提供方重试可能增加调用。使用该模型的正常额度与计费，未必等于当前会话选择的模型；后续在会话里发送任务也正常计费。第三方候选服务可能另有账号、Key 或费用。

从需求提炼的查询词会用于 GitHub 及已配置市场的搜索；Awesome 索引下载后按任务匹配。候选包清单与 README 来自对应 npm／GitHub 来源。需求、确认后的意图和候选资料会发送给宿主配置的模型，沿用宿主的模型提供方与日志策略；这不是离线推理。

会话接续使用官方 `uiWorkspace.connectWorkspace` 和保留的精确会话绑定调用原生草稿服务。仅在 `applied` 后打开目标会话；`preserved` 表示已有草稿或附件被保留、本次方案没有写入；`blocked` 表示草稿暂不可写。后两者保留本页方案供处理或复制。准备草稿不代表已经发送或执行。

历史保存仅用于本机接续，与提交需求给模型、公开反馈是不同数据路径；「新需求」不会删除旧方案、原生草稿或反馈。本版不读取用户所有会话来推断需求、不自动判断候选是否已安装、不自动验收组合，也不回读后续任务结果。主动保存的反馈关联具体任务版本；旧版未关联的反馈单独展示，不猜测归属。每个任务上限为 8 MB UTF-8 JSON，其中预留 1 KB 给恢复来源；达到上限会保留旧版本并报错，不静默裁剪历史。本插件不自动联系作者或创建 Issue。公开反馈由用户自行提交到 [GitHub Issues](https://github.com/piggy00544/dsh-plugin-finder/issues)。

## 开发

克隆源码后运行；安装用 tarball 不包含开发脚本和测试。DSH SDK 由宿主提供：

```sh
npm ci --ignore-scripts --legacy-peer-deps
npm test
npm run build
npm pack
```

仓库保留的旧静态 catalog 仅供历史研究与测试参考，生产发现路径不加载它。`npm run catalog:refresh` 是该历史资料的维护命令，不是新版的动态发现开关。
