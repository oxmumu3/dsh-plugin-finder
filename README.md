# 发现好插件 · DSH Plugin Finder

[安装说明](docs/install.md) · [验证记录](docs/verification.md) · [反馈](https://github.com/piggy00544/dsh-plugin-finder/issues/new?template=feedback.yml)
在 DeepSeek Harness 里描述一件要完成的事，确认需求，找到相关插件与最小方案，再带着草稿回到原生会话继续。

**当前为 `0.1.0-preview.1`。** 首版附带 15 个真实 DSH bundle 的来源索引；候选的包清单、固定版本或提交及作者文档可追溯。收录、版本声明相符、安装成功、任务完成是不同的证明状态。目录目前以元数据核对为主，不代表候选经过安装、任务或组合验收。

本地隔离验收已跑通真实模型理解、单插件推荐、原生未发送草稿接续、已有文字草稿保留及本机反馈落盘。公开下载和第二个干净 profile 的安装／卸载复验结果，以对应 [GitHub Release 的验收记录](https://github.com/piggy00544/dsh-plugin-finder/releases/tag/v0.1.0-preview.1) 为准；本地验证范围见 [验证记录](docs/verification.md)。

## 能做什么

- 在 DSH 原有侧栏增加一个「发现好插件」入口，右侧主面板完成需求理解、编辑、检索与推荐，保留宿主会话和工作区。
- 把目标拆成材料、产出、约束、所需能力与搜索词，再从附带索引中召回少量候选。推荐允许原生能力够用、单插件、最多两个插件的组合，或明确缺少供给。
- 展示候选的作者来源、精确安装 spec、版本、兼容声明、使用前提及核验状态。需要安装时跳到 DSH 插件页，由用户和宿主管理器确认；本插件不自动安装候选。
- 选择实际工作区后，核对宿主返回的目标会话与草稿状态；只有新草稿已应用时才切回会话。已有草稿或附件被保留、草稿暂时不可写时，保留当前方案并提示下一步。不会自动提交或执行任务。
- 用户主动记录「完成／部分完成／没能完成」，反馈仅保存在本机，最多保留最近 100 条，不自动联系作者或回传到本项目。

## 安装与首次使用

包声明支持 **DSH `0.2.0-rc.2` 或 `0.2.1-rc.2`**，Node `>=22.13`。这是一份版本兼容声明，实际安装、界面、模型及会话验证状态分别见 [验证记录](docs/verification.md)。

从对应发布页下载 `dsh-plugin-finder-0.1.0-preview.1.tgz`，通过自己使用的官方 DSH 插件管理器安装，或使用匹配版本的官方 CLI。详细步骤、卸载与排障见 [安装说明](docs/install.md)。本项目暂不要求注册独立账号或填写新的模型 Key。

打开「发现好插件」后：

1. 描述任务；先不用准备真实文件或安装候选。
2. 点击「理解这个需求」，检查并修改目标、材料、产出和约束。
3. 点击「确认需求，搜索并推荐」，阅读方案的能力分工、来源、前提和限制。
4. 如需候选插件，去宿主插件页核对和安装。返回后选择任务所在工作区，点击「确认方案，去会话继续」。
5. 在原生会话核对草稿和材料后自行发送。任务完成后，回到本页记录实际结果。

首屏读取索引和配置不会调用模型。需求理解和推荐属于辅助分析：沿用宿主的模型与账户，在模型声明支持时选择较低推理档（优先 low），不修改全局设置。完整的「需求理解 → 方案推荐」流程通常调用宿主全局默认模型 **2 次**；重新理解或推荐会增加调用；宿主或模型提供方的重试也可能增加实际请求。沿用该配置的账户、额度和计费规则，不保证等于当前会话选择的模型。之后在原生会话发送任务也按宿主规则计费。候选插件所依赖的第三方服务仍可能需要额外账号、Key 或费用。

## 可以直接试的三个任务

**本地 CSV 周报**

```text
我每周收到本地投放 CSV，想先检查缺失、重复和异常，再生成一份说明指标变化的周报。不接额外第三方账号。请先明确还需要哪些文件和业务口径，找一个最小可行方案，不要为了组合而加插件。
```

成功标准：需求理解保留本地文件与账号限制；推荐解释覆盖哪些能力、哪些判断仍需人工确认；方案带到正确工作区，草稿处于未发送状态。

**当前项目代码审查**

```text
我想审查当前工作区里的代码改动，找出能用具体代码证据说明的缺陷，并给出修改建议。不要自动修改文件，也不要把代码上传到新的第三方服务。请说明 DSH 原生能力是否已够用，额外插件能补什么。
```

成功标准：允许原生够用或有证据的单插件方案；不把目录收录当作能力验证；草稿明确只读边界和需要先确认的代码范围。

**测试真实供给缺口**

```text
我想把一个未对外开放的银行内部审批系统接入 DSH，读取待办并回写审批结果。我没有提供接口文档、授权或现成连接器。请只推荐有来源支持的能力；如果缺少合适插件，明确缺在哪里，以及继续之前需要我提供什么，不要假定已经可以连接。
```

成功标准：不编造连接器、授权或安装地址；解释缺口和需要补充的信息，仍能把待确认事项带入会话。模型输出存在不确定性，若未达到上述标准，请记录为未完成或部分完成。

## 数据与边界

需求描述、确认后的意图和候选资料会发送给 DSH 当前配置的全局默认模型，沿用宿主的模型提供方与既有日志策略。本插件没有独立的模型账户或自动作者回传；不要把「反馈仅本机保存」理解为模型推理离线运行。

运行时使用随包附带的索引快照，不自动抓取全网、启用自定义市场或修改用户的市场源。它没有读取用户所有会话来推断需求，也不判断候选是否已经安装。版本过滤只检查声明，不能代替实际安装和任务验证。

会话接续先通过官方 `uiWorkspace.connectWorkspace` 取得目标会话，再保留并核对该会话的绑定，调用原生草稿服务。只有返回 `applied` 时才打开会话并显示「草稿已准备」；`preserved` 表示已有草稿或附件被保留、本次方案没有写入；`blocked` 表示草稿暂不可写。后两种情况都会保留本页方案，供用户处理已有内容或复制建议草稿。草稿准备成功不代表任务已发送或执行。

首版不自动回读后续会话结果，也不自动验证多插件衔接。任务完成后需要用户返回记录反馈。反馈条目只包含结果选项、候选 ID、补充说明、阶段、时间及随机 ID，最多保留最近 100 条；不会把完整原始需求自动附到反馈里。

## 反馈与开发

需要向项目作者反馈时，请在 [GitHub Issues](https://github.com/piggy00544/dsh-plugin-finder/issues) 自行提交。本机反馈不会自动变成公开 Issue。建议只附 DSH／插件版本、问题步骤、预期与实际行为，分享截图或日志前自行去除敏感内容。

以下开发命令在克隆本项目源码后运行；安装用 tarball 只包含运行所需文件，不包含开发脚本和测试。DSH SDK 由宿主提供，按下述参数安装开发依赖，避免 npm 尝试另行拉取宿主 SDK peer 包：

```sh
npm ci --ignore-scripts --legacy-peer-deps
npm test
npm run build
npm pack
```

`npm run catalog:refresh` 从固定的 GitHub HTTPS 来源刷新索引元数据，不安装或执行候选包；请审阅差异后再分发更新。
