# 发现好插件 · DSH Plugin Finder

**你说想做什么，它先找现成的；不够的，再帮你补齐，最后接回原任务。**

不用先逛 6,500 个插件目录，也不用先学会写插件。

作者：牛村木木山 · MIT · 社区开源项目，非 DeepSeek 官方产品。

## 不用读插件目录

三个真实会遇到的场景：

- **每周一早上要一份项目周报。** Finder 先看你已装的能力能不能直接拼出来；缺一块，只为那一块找或补插件。
- **文章写完了，想配一套封面和卡片。** 现成的设计类插件能覆盖就直接用，不重复造。
- **想读一批论文并整理提纲。** 文献库、翻译、笔记如果已有合适组合，就保留组合，只补缺的环节。

它把「理解需求 → 核对现成能力 → 组合 → 补缺口 → 接回原任务」放在同一个工作区。能用现成的直接用；只覆盖一部分，就保留现成部分，只为缺失部分创建插件。

## 三步

1. **装。** 打开 Harness 的「插件 → 添加插件」，填 `@oxmumu3/dsh-plugin-finder`，安装后立即启用。
2. **说。** 点「帮我找方案」，用一句话说目标、约束和想要的产出；要调整就继续补一句，原输入和旧方案都会保留。
3. **用。** 方案里写清复用了哪些能力、为什么还要补。现成的可直接安装；缺的补齐后接回原任务，执行回复、审批和文件预览留在当前页面。

```bash
# 网页版也可以用命令行
dsh plugin --profile web add @oxmumu3/dsh-plugin-finder
```

## 它会做什么

- **先核对再动手。** 查来源、包身份、固定版本、兼容声明；来源核对不了、审批没完成、状态未知时，不冒充已安装、不提前执行。
- **组合优先。** 单个插件合适就一个；需要组合时保留 2–4 个现成插件；混合方案明确每个缺口和原因。
- **装完再跑。** 通过官方管理器完成安装与启用，确认实际加载后才开始执行；不需要你再去插件管理器点一遍。
- **回到原任务。** 方案不是终点，执行结果和可读的文件预览回到当前工作区。

## 它不会做什么

- **不把方案当成已安装。** 「计划复用」和「待补齐」描述的是计划，不是成功证明。
- **不把一轮结束当成需求完成。** 宿主一轮结束只表示运行结束；文件、安装状态和你是否满意要分别看。
- **不在缺信息时硬猜。** 真正缺少关键输入或权限时才请你判断；模型返回的结构不合格时先在同一需求内校对一次，仍不行就停下，不降低来源标准。
- **不替你扩大范围。** 任务绑定当前工作区；插件安装作用于当前 profile，不是独立沙箱。

## 在普通对话里也能用

你不需要先打开 Finder 再讲一遍背景。直接向标准 Agent 交代原任务，能力不够时它按需调用 Finder 核对、安装或补齐，再回原会话执行。边界见[主 Agent 说明](docs/agent-entry.md)。

## 在创造模式里自动带上经验

装上后，DSH 官方创造模式的会话会自动按更省 Token 的顺序做：先用 Finder 查有没有现成插件，再用三五句话对齐设计，第一版只跑通不白屏的空架子，改完说清该刷新还是该重启，同一个问题卡 3 轮就停下总结。这段提示只加给创造模式会话，普通会话不受影响。

- 说「记入插件经验：……」，经验会存进 Finder，之后新开的创造模式会话都能读到。
- 输入框上方显示进度：查现成 → 定设计 → 空架子 → 加功能 → 验证；卡住时可以一键开新窗口，把已记录的进展放进输入框接着做（不会自动发送）。
- 不想要时，在进度条上点「关闭」，或在 Finder 面板底部的「创造模式经验」里关掉。

## 精选与插件商店

首页保留一个需求输入、同屏一张建议，下面是精选和六类插件商店。浏览插件时先看用途、作者、版本和前提，再决定装不装；浏览与安装本身不调用模型。社区目录沿用六类快照（当前 6,563 条），这是已保存的规模，不是实时活跃插件数，也不是运行质量认证。

## 版本与兼容

当前 `@oxmumu3/dsh-plugin-finder@0.12.0-preview.13`，目标官方 Harness `0.2.1-rc.5` 与 `0.2.2-rc.1`（后者要求宿主 Node `>=24.9.0`），Node `^22.19.0 || >=24.0.0`。其他 RC、next 或实验 alpha 不据此推断兼容；安装状态以 npm 精确版本、Release 和最终验收记录为准。

Finder 沿用宿主配置的模型与账户，无需另填模型 Key；理解需求、检索、补齐和执行会使用相应额度。第三方插件可能另有服务、授权与费用。

## 数据与边界

需求、方案修订、原生草稿、反馈和执行关联保存在本机；查询词会用于外部检索，需求与候选资料会交给宿主配置的模型。集中摘要回传默认关闭，与机会发现的资料授权是两件事；明确同意后只处理后续新操作，不批量补传旧历史。完整范围见[数据回传说明](docs/data-sharing.md)。
