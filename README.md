# 发现好插件 · DSH Plugin Finder

你说需求，现成的先用，缺的帮你补，最后接回原任务。

Finder 把需求理解、现成能力选择、插件组合和缺口创造接在同一个工作区。能用现有能力完成，就直接用；现成插件只覆盖一部分，就保留这些能力，只为缺失部分创建插件。首页、精选和插件商店都是这位插件专家的入口。

**版本：`@oxmumu3/dsh-plugin-finder@0.12.0-preview.2`。** 准确目标仅为官方 Harness `0.2.1-rc.5`，Node `^22.19.0 || >=24.0.0`。正式安装状态以 [Release 列表](https://github.com/oxmumu3/dsh-plugin-finder/releases)、npm 精确版本和最终验收记录为准。

## 从一句需求到可用结果

1. **说出想完成的事。** 点「帮我找方案」，Finder 连续理解目标、约束并核对现成能力。需要调整时继续补一句话，原输入和旧方案保留。
2. **使用现成能力，或保留现成部分再补齐。** 单个插件合适就使用一个，组合方案可选择 2–4 个现成插件。混合方案保留 1–4 个现成插件，明确每个具体缺口及原因；点「补齐并使用」，系统沿用原目标，只创造缺失部分，再接回原任务。真正缺少关键输入或权限时才请你判断。
3. **在同一工作区看结果、继续修改。** Finder 通过官方管理器完成所选插件的首次安装与启用，确认实际加载后才开始执行；无需另外去插件管理器。执行回复、必要审批和实际文件预览留在当前页面。你也可以主动定制自己的插件。

原生能力足够时无需为了使用 Finder 而增加插件。任务执行绑定当前工作区；插件安装作用于当前 Harness profile，不是独立安装沙箱。已有版本或来源冲突时保留现有插件；来源无法核对、审批未完成或状态未知时，不冒充已安装，不提前执行或盲目重装。

模型返回的方案结构未通过校验时，系统会在同一需求和同一轮候选资料内校对一次，不要求重新输入或重复搜索。仍不能确认时保留原理解，停止安装与执行；不会降低来源和能力校验标准。

## 看懂方案，也看见成果

首页保留一个需求输入、同屏一张建议，下方是精选与六类插件商店。方案说明计划复用哪些能力、为什么还需要补齐；运行区域优先呈现实际会话和可读取的文件预览，来源、完整方案与历史可以展开查看。

「计划复用」与「待补齐」描述的是方案，不是安装或成功证明。宿主一轮结束只表示运行结束；文件产出、安装 active、实际功能与用户目标是否满足仍需各自证据。没有读到真实结果时，不显示“需求已解决”。

## 精选与插件商店

浏览具体插件时，详情保持同一插件身份，先看用途、作者、版本和前提，再直接安装或启用；不会把卡片描述送去生成另一份需求方案。浏览与安装本身不依赖模型，返回后保留筛选与分页。

精选包含 AI 分身、微信家庭助手、DSH Dot 和 Dot 连接 Harness。安装项目助理或连接管理插件不等于微信、账号或云端通道已连接，仍需本人配置和单独验证。

社区浏览沿用六类目录快照，当前有 6,563 个条目，每类先展示三个，进入后可搜索、筛选和翻页。这是已保存的社区资料规模，不是实时活跃插件数，也不是运行质量认证。完整来源与快照时间在页面显示；策展不代表官方背书。

## 先给一个想法，也可以参考你授权的资料

尚未开启个性化时，推荐位显示可尝试的具体想法，并明确标为「通用想法」或「本机线索」；不会把固定场景称为模型已经理解了你。

首页可一次明确授权最近最多三份 Finder 需求与摘要给当前模型。摘要范围为原始需求、目标、预期产出与约束；不会因此读取整个项目、其他文件、完整会话或浏览记录。也可以在参考信息中自行选择有限的 Finder 方案与当前工作区文本文件。实际读取、模型提供方和日志沿用宿主设置。

已有授权会在原范围内复用；需要更新建议时可能重新读取已选材料并调用模型，可以随时停止个性化。配置与本机记录读取本身不调用模型；已开启的机会发现是单独的模型动作。建议带依据，采纳后才查找与执行方案。

## 在主 Agent 的原任务中使用

用户也可以只向标准 Agent 交代原任务。能力足够时它继续完成；需要额外能力时按需调用 Finder，核对、安装或补齐，再回到原会话执行。用户无需先进入 Finder 再讲一次背景。工具与权限边界见[主 Agent 说明](docs/agent-entry.md)。

## 安装与兼容

通过当前官方 Harness 原生「插件 → 添加插件」安装精确 npm 来源 `@oxmumu3/dsh-plugin-finder@0.12.0-preview.2`。发布状态以 npm 精确版本与 Release 回读为准；尚未同步时保留当前安装。已有预览包不得仅因版本号较大就覆盖另一条有效修复线。

本版目标为官方 `0.2.1-rc.5`；四个官方 SDK peer 均固定同一版本：`@deepseek-ai/dsh-app-boot`、`@deepseek-ai/dsh-storage-domain`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-sandbox`。Node 要求为 `^22.19.0 || >=24.0.0`。其他 RC、next 或实验 alpha 不据此推断兼容；安装、启用、卸载/重启与最终包的真实验证范围，以对应发行版的验收记录为准。

Finder 沿用宿主配置的模型与账户，无需另填模型 Key；需求理解、搜索分析、机会发现、创建及执行会使用相应额度。第三方插件可能另有服务、授权与费用。[安装与迁移说明](docs/install.md)包含 profile、旧安装和数据保留边界。

## 来源、历史与数据

Finder 按需读取 [Awesome DSH 社区目录](https://awesome-dsh-plugin.com/)、用户已配置的官方市场源，并在有界预算内补充 GitHub 插件来源。核对作者资料、包身份、固定版本/提交、兼容声明与安装来源后组织方案。搜索有覆盖和时间预算；来源失败或候选未读完不等于市场不存在合适能力。查询词会用于外部检索，需求与候选资料会交给宿主配置的模型。

原任务、方案修订、原生草稿、反馈及执行关联保存在本机。重新打开原记录只观察原执行，不自动重发；结果未知时保留原回执，不盲目重试。可导出单任务 JSON 备份，分享前检查私人信息。停止不撤销已经发生的操作。

集中摘要回传默认关闭，也不是使用前提；与机会发现的资料授权是不同设置。明确同意后仅处理后续新操作，不批量补传旧历史；共创及其派生记录只存本机。停止回传不等于删除服务端已有记录。完整范围见[数据回传说明](docs/data-sharing.md)。
