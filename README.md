# 发现好插件 · DSH Plugin Finder

[安装说明](docs/install.md) · [当前工作区流程](docs/workspace-flow-preview.md) · [数据回传说明](docs/data-sharing.md) · [历史验证记录](docs/verification.md) · [反馈](https://github.com/oxmumu3/dsh-plugin-finder/issues/new?template=feedback.yml)

**本次发布版本：`0.9.0-preview.10`，公开预览版。** 描述你要完成的事，Finder 分析需求、查找插件并组成方案。合适就点「使用这个方案」，直接在当前工作区执行；不满足就「创建自己的插件」，点「开始创建」后在原处启动创建。

执行功能要求官方 DSH `0.2.1-rc.2`。`0.2.0-rc.2` 可搜索和查看历史，不支持本版直接执行。Finder 沿用宿主模型，无需另填模型 Key。

本版提供六类社区插件浏览、自然语言匹配、当前工作区使用和官方 Creator 创建。自动首次安装已用此前未安装的 `dsh-tool-qrcode@1.0.0` 实跑：真实搜索、点击「使用这个方案」、自动安装启用、调用插件并生成可独立解码的 SVG；未提前安装或手工补发执行指令。首次执行在 preview.9 完成，preview.10 补安装许可提示，并通过刷新恢复同一结果、不重复安装或执行验证。创建路径沿用 preview.8 的真实 Creator 创建、安装与操作证据，本轮没有重跑创建。全套回归 651 项通过；这些场景不代表已逐个验证全部社区插件。

## 从需求到实际结果

1. **说需求**：输入要做的事，点「帮我找方案」。系统连续理解、搜索和组织方案；需要补充时，继续说明即可。
2. **使用方案**：查看能得到什么和关键前提，点「使用这个方案」。Finder 自动安装、启用所选插件，确认加载正常后在当前工作区启动执行；本页显示进度、结果及必要的宿主授权。无需另去插件管理器。
3. **需要自己的插件**：方案不满足时点「创建自己的插件」。已有需求继续沿用，只补真正缺失的信息；点「开始创建」后，官方 Creator 在同一工作区执行。

系统优先根据当前会话所属工作区、或唯一可用工作区确定目标；只有没有可靠目标时才请用户选择。复制、另开项目、预览草稿和交接材料都不是主路径步骤。插件安装作用于当前 Harness profile，任务在绑定的工作区执行；不会改装同名其他来源、卸载或替换已存在的冲突版本。安装失败或状态未确认时保留原方案，不提前发送执行任务。额外权限与构建脚本审批仍沿用宿主规则。

任务、方案版本和执行会话保持精确关联。重新打开历史会接回原执行记录，只观察进度和结果，不重新发送任务；不因网络状态未知而自动重试执行。旧方案、未发送输入和草稿继续保留。

## 还没想好做什么

首页右侧提供一个具体场景：没有偏好依据时显示「试试这个」，本机历史或明确兴趣提供依据时显示「猜你喜欢」。场景帮助你形成需求；底部固定保留「精选插件」，可浏览 AI 分身、微信家庭助手、DSH Dot 和 Dot 连接 Harness 四组用途。

卡片说明用途、前提、来源和验证边界。自研策展不等于官方审核；预览与私有作品不提供未经核对的安装入口。兴趣和推荐调整收在次要入口，不增加首页导航标签。

精选下面增加「按用途找插件」：六类各展示三个用途清楚的条目，点「查看全部」即可在同一区域搜索、筛选和翻页。当前快照可浏览6,563条，点击「查看使用方案」核对所选插件来源、能力和前提，再接回原来的使用流程。浏览本身不调用模型、不安装插件。

分类点选会绑定所选作者和子目录，读取该条目的实际资料；缺项或不兼容会说明原因，不无声换成同名插件。选择保存在本机历史中，编辑需求不会悄悄丢掉它；首页可明确取消指定。

目录元信息来自 [Awesome DSH Plugin](https://awesome-dsh-plugin.com/) 的 CC0 数据。源快照有6,565条，其中两个自有旧账号条目因正式归属尚未迁移而不展示；来源与计数不同于安装或质量验证。18个首页条目只核对了作者用途说明，不构成热门榜或功能认证。

## 安装公开预览版

本次版本的 [Release](https://github.com/oxmumu3/dsh-plugin-finder/releases/tag/v0.9.0-preview.10)、[安装包](https://github.com/oxmumu3/dsh-plugin-finder/releases/download/v0.9.0-preview.10/dsh-plugin-finder-0.9.0-preview.10.tgz)与 [SHA256SUMS](https://github.com/oxmumu3/dsh-plugin-finder/releases/download/v0.9.0-preview.10/SHA256SUMS)使用固定版本地址。

在正在使用的 DSH 原生「插件 → 添加插件」中，粘贴以下完整安装来源，按宿主提示安装／更新并启用：

```text
https://github.com/oxmumu3/dsh-plugin-finder/releases/download/v0.9.0-preview.10/dsh-plugin-finder-0.9.0-preview.10.tgz
```

确认实际版本为 `0.9.0-preview.10`，打开侧栏「发现好插件」。这一步只用于安装 Finder；此后使用方案中的所选插件由 Finder 自动安装和启用，无需再去插件管理器。包要求 Node `>=22.13`，宿主兼容与 CLI 安装见[安装说明](docs/install.md)。

**历史公开版本 `0.3.0-preview.2` 继续保留。** [历史 Release](https://github.com/oxmumu3/dsh-plugin-finder/releases/tag/v0.3.0-preview.2) 与 [历史安装包](https://github.com/oxmumu3/dsh-plugin-finder/releases/download/v0.3.0-preview.2/dsh-plugin-finder-0.3.0-preview.2.tgz) 保留用于追溯，不包含本页描述的当前工作区执行与分类浏览流程。旧版本的草稿接续方式不作为本版使用说明。

**npm 渠道正在准备。** 现有 GitHub 安装入口继续有效；候选 npm 包名尚待发布账号确认，暂不提供未发布包的安装指令。已有用户无需为此重新安装。发布维护流程见 [npm 分发说明](https://github.com/oxmumu3/dsh-plugin-finder/blob/main/docs/npm-publishing.md)；同一 Finder 的新旧包不应同时启用。

## 从哪里发现插件

- **Awesome DSH 第三方目录**：按需读取[完整目录](https://awesome-dsh-plugin.com/plugins.json)，检索 npm 与 GitHub-only 记录；[format-1 市场索引](https://awesome-dsh-plugin.com/index.json)作为补充。它不是 DSH 官方审核目录。
- **用户已配置的 DSH 市场**：通过宿主搜索已有源；未配置就明确显示，不自动更改市场源。
- **GitHub `dsh-plugin` topic**：按需求进行有界补充检索。

召回后，在 24 条候选、全轮 45 秒、每候选 8 秒的预算内核对最多 6 个候选。系统读取相关作者包清单和 README，核对包身份、版本／提交、bundle 声明、兼容前提及安装来源，再交给宿主模型分析。README 未读到、被截断或版本可能不一致时保留提示。作者声明、成功读取资料和实际功能验收是不同证据。

索引与 JSON 读取使用 5 分钟内存缓存，用户市场缓存由宿主管理。来源、时间、缓存和覆盖状态可以展开查看；部分来源失败表示覆盖不完整，全部来源不可用时报搜索错误，不把网络失败解释为没有插件。跨来源条目可能重叠，数量不能相加当独立插件数。

这是所列来源内的动态检索，不穷尽全网。方案可以使用原生能力、单个插件或最多两个插件的组合，也可以明确指出缺口；目录规模、GitHub 热度和会话结束都不代表任务成功。

## 历史、数据与反馈

「历史方案」可回看任务、版本、候选资料、反馈和精确执行关联。新需求不会删除旧方案或原生草稿。单任务 JSON 导出／导入用于个人备份，可能包含私人需求，分享前请检查；已删除的旧记录需要已有备份才能恢复。

每个本机任务的业务历史上限为 8 MB UTF-8 JSON，其中预留 1 KB 给恢复来源；达到上限会保留旧版本并报错，不静默裁剪。集中摘要队列另有每任务 256 KB 上限，未入队会明确提示，本机保存不等于已回传。

**集中摘要回传默认关闭，也不是使用前提。** 明确同意后，只对后续新操作同步有界需求、方案和反馈摘要及必要插件版本上下文，不批量补传历史。摘要会清理常见路径、邮箱和凭据格式，但不能保证识别所有敏感内容。回传路径不读取文件、完整会话或模型凭据；共创及其派生记录只存本机。停止回传和删除已回传记录是不同操作，删除以服务端确认作为依据。详见[数据回传说明](docs/data-sharing.md)。

主动保存的反馈属于用户自报，不等于已验证安装或任务成功。给作者的反馈导出是可选辅助，不自动发送、创建 Issue 或变成使用流程的一部分。

## 模型与执行边界

首屏读取配置和本机记录，不调用模型。需求理解和推荐沿用宿主全局默认模型及账户；模型支持时使用较低推理档，不修改全局设置。匹配通常调用模型两次，修改、重试和执行会产生后续调用，沿用相应模型的额度与计费。第三方服务可能另外要求账号、授权、Key 或费用。

查询词会用于 GitHub 与已配置市场搜索；需求、理解后的意图和候选资料会交给宿主配置的模型，沿用其提供方与日志策略。这不是离线推理。

点击执行后，Finder 创建并绑定对应的普通会话或官方 Creator 会话，提交一次任务，在当前页面呈现宿主执行内容、必要输入与审批。会话的 `turn_completed` 只表示该轮结束；文件产出、插件安装、首次运行及用户目标是否实现，仍需分别核验。停止也不撤销已经发生的操作。

## 开发与历史记录

源码开发命令如下；安装 tarball 包含预构建客户端，不包含开发脚本和测试。DSH SDK 由宿主提供。

```sh
npm ci --ignore-scripts --legacy-peer-deps
npm test
npm run build
npm pack
```

旧 `catalog/index.mjs` 静态样本只保留作历史研究和测试，生产动态发现路径不加载它；新增 `src/community-catalog-data.js` 是单独的可浏览社区快照。`npm run community:build` 从已审计研究快照重建它，不自动联网更新。`npm run catalog:refresh` 只维护该历史资料。
